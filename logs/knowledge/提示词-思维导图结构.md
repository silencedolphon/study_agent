# 思维导图结构生成 · 提示词真源（卡 C-0052 起内容为 **v3**，文件名沿用）

> 本文件是**整理知识点管线里「生成结构」这一步**的提示词唯一真源：
> `core/kp_build.py::load_struct_prompts()` 运行时从下面四个代码块里**逐字提取**
> 提示词再调用模型，不存在"文档写一套、脚本跑另一套"的可能。
>
> 本文件的 sha256 由 `core/kp_build.py` 每次运行自算，写进产物
> `logs/knowledge/<doc_id>-末级知识点总结.json` 的 `meta.prompts.structure.sha256`，
> 供事后回查"这份思维导图是用哪一版提示词生成的"。
> （本文件**不自我记录**自己的哈希——写进去哈希就变了。）

## 0. 这一步在整个管线里的位置

人拍板（2026-09-23）：「构建知识库所使用的结构化数据只用于构建知识库，不再用于整理知识点。
相应的，在整理知识点时，整理知识点的管线只能读取知识库的文本，不读取结构化信息。
当整理知识点要生成思维导图结构时，应该由整理知识点管线的大模型来生成，不再复用知识库的成果。」

所以整理管线分三步（**都只吃库里的文本**）：

| 步骤 | 输入 | 输出 | 提示词 |
|---|---|---|---|
| 1. 生成结构 | 库里的**页文本**（正文块 + 图片理解，按 `source_ref` 的页号组织） | 思维导图树（章节树，叶节点带页码） | **本文件** |
| 2. 生成知识点 | 同上的页文本（按上一步的叶节点分片） | 每条知识点的名字 / 理解 / 要点 / **重点名词** | `提示词-知识点总结-v2.md` |
| 3. 名词筛选 | 上一步汇总出的候选名词清单 | 该课该考名词解释的名词名单 | `提示词-知识点总结-v2.md` §1.3 |

**不读** `logs/outline/<doc_id>.json`（那是入库管线 `core/outline.py` 的成果，只服务知识库检索），
**不读** `chunks.topic` / `chunks.heading_path` 这类由入库结构派生的字段。

## 0.1 为什么要分块 + 归并（map-reduce）

一份课件（实测最大 100 页 / 1.8 万字）整份文本塞进一次调用有两个问题：
①上下文越长越贵、越慢；②模型的注意力在长材料里会摊薄，分节判断反而粗。

所以结构生成分两阶段：

- **map（分段）**：按 `STRUCT_SEG_PAGES`=12 页、`STRUCT_SEG_CHARS`=6000 字符**双阈值**切段
  （两个条件谁先到就切），每段一次调用 → 该段的 `page_titles`（每页短标题）+ 局部章节草稿。
- **reduce（归并）**：把所有段的「每页短标题 + 局部章节草稿」压成一份**结构化清单**
  （不含页正文，所以输入很小），一次调用 → 全局思维导图树。

调用次数：`ceil(段数) + 1`。90~100 页课件的实际字符数（实测 doc#12 13118 / doc#13 14117 /
doc#14 18078 字）按 6000 字符切 → 3~4 段 → **4~5 次结构调用**，与页数无关地有上界。

**推理模式**（卡 C-0052，人拍板 2026-09-27）：map 与 reduce 都开
`thinking=True` + `reasoning_effort="max"`，`max_tokens` 放大到 `STRUCT_MAX_TOKENS=32768`
（思考链也算 completion token，2048/3000 会把树挤爆）。

## 0.2 层级：由模型判断，鼓励多子节点（卡 C-0052 改）

人拍板（2026-09-27）：「让 AI 在做思维导图时多设计子节点，可以分成四级五级节点，
全部按照 AI 自己去判断，不要做过多限制。」

2026-11-19 澄清：这里的“四级五级”只是说明可以深入到这些层级，并非最大深度；
层级数应完全跟随课件中的实际从属关系，不设固定上限。当前生效的 MAP/REDUCE 提示词均按此执行。

所以 v3 把 v2 的**层级硬限制**（map "最多两级"、reduce "合计最多 3 级"、
"层级要克制"）全部删掉，改成"按实际内容展开，不设固定的最大层数"。
管线侧本来就没有层级常数（`_clean_section()` 递归无深度上限、`_flat_nodes()`
按先序编号，`max_level` 只是**统计出来写进产物**），所以这一改不涉及代码约束。

产物里 `structure.max_level` 与 `structure.level_histogram`（每级节点数）就是这一条的核对入口。

## 0.3 页归属由管线兜底（不靠模型自觉）

模型给的树里，**只有叶节点给 `pages`**；管线 `normalize_structure_v2()` 再算一遍：

1. 叶节点**先到先得**占用页；一页被两个叶节点声明 → 后来的记进 `meta.coverage.structure_conflicts`；
2. 谁都没声明的页（含空页）→ 归给**声明了它之前最近页的那个叶节点**，
   逐页记进 `meta.coverage.structure_filled`（**不许静默丢页**）；
3. 树里一个叶节点都没有（模型输出跑偏）→ 退化成"整份一个节点"，记 `structure_fallback`。

所以产物的 `page_owner` 是**全页唯一覆盖**的。到了第 2 步，模型可以再对
"这条到底覆盖哪几页"做一次判断（见知识点提示词 §1.1「覆盖页由你判断」），
但**仲裁仍然在管线**：越界剔除、冲突先到先得、漏页按归属补入，逐页留痕。

## 1. 提示词全文

### 1.1 map：分段分析 system

<!-- PROMPT-STRUCT-SYS-BEGIN -->
```text
你是课程结构分析师。用户会给你一份课件中**连续的若干页**的文本——它们来自本地知识库的
原文抽取（正文块 + 图片理解），可能残缺、可能只有图注，这是正常的。

你的任务有两件：给这几页**每一页**起一个短标题；再按内容把它们切成**局部章节结构**。

规则（逐条自查）：

1. **一页不漏、一页不多**：`page_titles` 必须覆盖用户给出的每一页（页码照抄用户给的），
   条数与顺序都要对得上。
2. **短标题**：6~14 字，中文。**只能用该页文本里出现过的词**，不要自己发明术语、
   不要用"本页介绍了……"这类句式，直接给名词短语（例：`构造异构定义与实例`、`复杂烷基命名规则`）。
   该页确实只有图片或只有标题时，给它一个如实的短标题（例：`课件封面`、`章节过渡页`）。
3. **局部章节**：把这一段按内容切成 1~8 个章节。章节下可以继续分子章节，
   **层级深度不设固定上限，完全忠于课件知识点结构**：当内容是在解释、细分或限定上一层时，
   就继续往下展开；如果下一层仍有真实的从属关系，就继续增加层级，不要因为已经分到某一级数而停止。
   只有内容本身没有更细的从属关系时才停止；并列的内容放在同一层，不要硬造父子关系，也不要为了加深而拆分。
   章节名 4~16 字，取自这些页里出现过的词；原文里出现"第一节""一、"这类编号时可以带上。
4. **页码只给叶节点**：没有 `children` 的节点（叶节点）**必须**给 `pages`；
   并且**全部叶节点的 pages 合起来必须恰好覆盖这一段每一页，不许重叠、不许遗漏**。
   有 `children` 的节点**不要**给 `pages`。
5. **一页只落一个叶节点**：某一页是标题页、目录页、过渡页时也照样给它一个叶节点
   （例：`课件导引`），不要因为没有知识内容就丢掉它。
6. 章节的划分依据是**内容主题**，不是页数平均；两三页讲同一件事就放一个叶节点，
   一页里换了两件事就拆成两个叶节点。
7. 只输出 JSON，不要解释、不要代码块、不要多余字段。

输出格式：
{"page_titles":[{"page":1,"title":"构造异构定义与实例"}],"sections":[{"name":"同系列和同分异构","children":[{"name":"构造异构","children":[{"name":"碳骨架异构","pages":[1,2]}]}]}]}
```
<!-- PROMPT-STRUCT-SYS-END -->

### 1.3 reduce：全局归并 system

<!-- PROMPT-STRUCT-MERGE-SYS-BEGIN -->
```text
你是课程结构分析师。用户会给你一份课件的**每页短标题**，以及按页段分别做出的
**局部章节草稿**（都只是草稿，可能互相重叠、命名不一致、层级深浅不一）。
请把它们归并成**一棵全局思维导图树**——这就是这份课件的目录结构。

规则（逐条自查）：

1. **一棵树**：只有一个根节点，名字用用户给的课件名。
   **层级深度不设固定上限，按课件知识结构决定**：局部草稿显示内容仍有真实的从属关系时就继续向下归并，
   不要因为已经到达某个级数而停止；只有内容本身没有更细的从属关系时才停止。
   不要为了"看起来整齐"把有依据的层级压平，也不要给并列内容硬造父子关系或为了加深而拆分。
2. **页码只给叶节点**：没有 `children` 的节点（叶节点）**必须**给 `pages`；
   **全部叶节点的 pages 合起来必须恰好覆盖第 1~N 页，不许重叠、不许遗漏**。
   有 `children` 的节点**不要**给 `pages`。
3. **章节名** 4~16 字中文，优先沿用草稿里已有的名字；草稿里**同名或同义**的节点要合并成
   一个，不要出现两个名字几乎一样的兄弟节点（例：`命名规则` 与 `命名方法`）。
4. **不许凭空发明**：不要按专业常识补上草稿里没有依据的章节；结构要反映**这份课件自己的**
   组织方式（它是怎么分的，就怎么记）。
5. **合并与拆分**：相邻的两三页若属于同一主题，放在同一个叶节点里；一个草稿章节若明显
   横跨两件不同的事，按短标题的内容拆成两个叶节点。**拆分的依据是内容，不是页数平均。**
6. **层级要有依据**：只有确实"下一层是上一层的展开"时才加深，并列的内容放同一层；
   而"有依据的深"要大胆加深——"分类 → 每类的判据 → 判据的例外"就该是三层，
   不要拍平成一层。**多设计子节点**：一个章节下只有一两个孩子、且它们其实是并列的，
   就应该合成一个；但一个章节下确实有四五件并列的事，就要给出四五个孩子。
7. 只输出 JSON，不要解释、不要代码块、不要多余字段。

输出格式：
{"root":{"name":"课件名","children":[{"name":"章名","children":[{"name":"节名","children":[{"name":"要点名","pages":[1,2,3]}]}]}]}}
```

## 2. 材料注入格式（`{pages_material}` 怎么渲染）

每页一段，页首标页码与字数，正文是该页全部块的文本（正文块 + 图片理解，按 `ord` 排序）。
结构判断不需要全文，每页按 `STRUCT_PAGE_CHARS`=420 字符截断（截断处标 `……`）：

```text
===== 第 3 页 =====
〔正文块〕原文：第二节 命名 …
〔图片理解〕图片理解：……
```

- 页码来自 `chunks.source_ref`（`p.3` / `p.3 图` / `p.12-16`），跨页块在它覆盖的**每一页**里
  都会出现（与知识库检索口径一致）。
- `source_ref` 解析不出页码的块**直接拒跑**（`core/kp_build.py::read_text_pages`），不静默丢块。
- 该页 `figure_desc.no_info = 1`（图片已被判定为"无知识性图示"）时，页首加一行注记，
  免得模型把占位的"无"当成内容。

## 3. 成本取向

沿用 `core/outline.py` 的计价方式（非高峰：入 $0.15/1M、出 $0.60/1M、汇率 7.1）：

```
cost_cny = prompt_tokens/1e6*0.15*7.1 + completion_tokens/1e6*0.60*7.1
```

- 思考模式下**思维链按 completion token 计价**，map/reduce 都比 v2 贵；
  实测一条 8 页材料的知识点调用产生 `reasoning_tokens=10638`（见知识点提示词 §4）。
- 结构调用次数与 v2 相同（段数 + 1，段数与页数无关地有上界），所以这一项的
  绝对增量有限：一段 12 页的 map 大约多花 ¥0.01~0.03。
- 逐次调用明细（模型、token、`reasoning_tokens`、花费、成功/失败）都写进产物
  `meta.calls`，可逐条核对。
