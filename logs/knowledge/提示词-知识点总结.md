# 末级知识点总结 · 提示词真源（唯一真源）

> 本文件是**知识点整理管线的提示词唯一真源**：`core/kp_build.py` 运行时从下面两个
> 代码块里**逐字提取**提示词再调用模型，不存在"文档写一套、脚本跑另一套"的可能。
> 改提示词只需改本文件，看板按钮与命令行跑出来的结果都会跟着变。
>
> 本文件的 sha256 由 `core/kp_build.py` **每次运行自算**，写进产物
> `logs/knowledge/<doc_id>-末级知识点总结.json` 的 `meta.prompt_sha256`，
> 供事后回查"这份总结是用哪一版提示词生成的"。
> （本文件**不自我记录**自己的哈希——写进去哈希就变了。）

## 0.0 C-0045 改了什么（父节点页下放）

人报的问题（原话大意）：*"父节点带着的 PPT 和子节点带着的 PPT 关系是连续的，
但父节点带着的 PPT 不进行归纳，导致子节点的 PPT 缺失了父节点那一部分，造成信息丢失。"*

实测（`subjects/有机化学`，doc#5《第二章 烷烃》34 页）：旧口径只覆盖 **23/34 页**，
**11 页 15122 字**（全文 **42%**）从未进入任何知识点——它们全是"在导图里还有下级
节点"的**上级节点页**。根因不在提示词，而在 `core/kp_build.py` 的页面归属逻辑：
旧版 `window_of()` 只从末级页起、遇父节点页即停，父页的材料根本没送给模型。

本版把提示词相应改成"材料里可能出现两类页"：

| # | 改动 | 必要性 |
|---|---|---|
| 1 | §「任务」开头讲清材料里可能有**上级节点页**，并给出页首注记的样子 | 模型看到一页排在自己前面，不知道它算不算本条的内容；不说明就会当成背景略过——内容还是丢 |
| 2 | 明确要求：上级节点页的内容**必须一并归纳**、页号**必须写进 `pages`** | "下放"要落地成产物必须靠 `pages` 表达；只写在 summary 里，机器无法核对它有没有丢 |
| 3 | 上下限改成"**末级节点页**最多 3 个，前面的上级节点页不计入但必须全带上" | 旧文案写"最多 3 页"，而一个窗口现在可能是"3 个上级页 + 1 个末级页"= 4~5 页；不改，模型会为了守 3 页而丢掉上级页 |
| 4 | user 模板新增 `下放给本条的上级节点页：{parent_pages}`，并把"可合并范围（最多 3 页）"改成"本次材料覆盖的连续页" | 让"哪几页是下放的"在**请求里**就显式可见，而不是只靠材料页首的注记；窗口页数已经不等于 3，标签必须跟着改 |
| 5 | 输出格式里补一句：材料第 1 页是上级节点页时，`pages` 就从它开始 | 旧文案"以材料第 1 页开头"与"含当前页"在新窗口下会打架，必须点明起点是材料第 1 页 |

配合的逻辑改动在 `core/kp_build.py`（`handoff_map()` / `window_of()` / `normalize_pages()` /
`_gen_one()`，见 `meta.coverage` 与 `meta.parent_nodes` 两节）：
父节点页**唯一归属**一个末级页宿主（同一节连续优先），材料并入它的窗口，
产物 `pages` 由管线**强制补入**（模型漏写也补），`coverage.overlap_pages` 必须为空。

v2 相对 C-0034 的改动**逐条对应人提的三点要求**：

| # | 人的要求 | 本文件怎么落 |
|---|---|---|
| 1 | 大模型**全部以中文输出，辅以专有名词的英文** | §「语言：全程中文，专有名词附英文」：name/summary/points/merge_reason 全中文；专有名词**首次出现**时中文后圆括号附英文（`拓扑异构酶 II（Topo II）`）；同一条内只附一次；整句英文禁止 |
| 2 | 根据**每页信息密度**与**上下页连续性**，**选择性合并**有联系的几页为一个最末端节点 | §「任务：先判断要不要合并，再写总结」：给出可执行的合并两条件（信息密度低 + 主题连续）、四条**不许合并**的负面判据、硬性上下限（1~3 页、连续、必须含当前页）与"拿不准就不合并"的默认；输出必须带 `pages` / `merged` / `merge_reason` |
| 3 | **精简要点**，提炼**结构、概念、过程、原因、结果**类关键知识点 | §「要写什么」的 points 条：**3~6 条**、每条 ≤40 字，且每条必须归入**结构/概念/过程/原因/结果**五类之一；明确禁止"截短 summary 当要点""拆句凑条数""凑数" |
| 4 | 保留既有防照抄约束 | §「禁止原文照录」+ §「必须改写的三类句子」**逐字沿用 C-0034**（概念定义 / 实验方法 / 并列清单必须改写，连续 ≥20 汉字算照录） |

除此之外的写法（材料只有正文块与图片理解、铁律只依据材料、insufficient 出口、
只输出 JSON）**与 C-0031/C-0034 一脉相承**，只是把"一个末级节点 = 一页"改成了
"一个末级节点 = 从当前页起连续 1~3 页"，因此材料是按**窗口**给的（见 §2）。

## 0.1 怎么用（调用方式）

- 入口：`core/chat.py` 的 `chat_once(messages, model=..., max_tokens=..., thinking=False, temperature=0.3)`
- `messages = [{"role":"system","content":<SYS>}, {"role":"user","content":<USER 渲染结果>}]`
- 一次调用只处理**一个知识点窗口**：窗口 = 下放给当前末级页的**上级节点页**（0~N 页）
  + 当前页 + 后续至多 2 个末级页；末级页最多 `MAX_MERGE`=3 个，总页数受
  `MAX_WINDOW_PAGES`=6 兜底（`core/kp_build.py::window_of`）。
- `model=deepseek-flash`、`thinking=False`、`temperature=0.3`、`max_tokens=2048`。
- 材料 = 窗口内每一页的**正文块 + 识图块**（识图块是**已入库的图片理解文本**，
  **不重新调用任何视觉模型**），全带上、不截断。
- 模型返回的 `pages` 由 `core/kp_build.py` **逐条校验**（升序、连续、含当前页、
  不越出窗口），并按**下放归属强制补入**上级节点页；不合法的合并一律降级为
  合法连续段并在产物里记 `merge.rejected_reason`——绝不静默接受一个越界的 `pages`。

## 1. 提示词全文

### 1.1 system

<!-- PROMPT-SYS-BEGIN -->
```text
你是为一份中文医药学课件编写**知识点总结**的助手。
你的读者是正在复习这门课的学生：他要的是**读懂并记住这几页在讲什么**，不是再读一遍原文。

## 材料只有两种，别的一律不算数

1. **正文块**：课件文字层的原文（每块前面标了出处，方括号里是块编号）。
2. **图片理解**：视觉模型对课件插图的解读，会标注「图片理解」。
   它**含推断成分，不等于书上原话**；转述它时不要写成"书上写"。

**铁律：只能依据【材料】里出现的内容写。**
- 材料里没有的药名、数值、机制、适应证、剂量、疗程，一个字都不许出现。
- 不许用你自己的专业知识补充、纠正或延伸材料里的内容。
- 不许按常识补全"显然应该有"的细节（某个结构属于哪一类、某个数值的单位换算）。
- 材料内部若有冲突，明确指出冲突，不要擅自取舍。
- 图片理解与正文冲突时以正文为准，并写明这一点。

## 语言：全程中文，专有名词附英文

- **name / summary / points / merge_reason 一律用中文写**，不许出现整句英文。
- **专有名词第一次出现时，中文后面用圆括号附一次英文原名**，例如
  `拓扑异构酶 II（Topo II）`、`脱氧核糖核酸（DNA）`、`微小 RNA（miRNA）`、
  `信使 RNA（mRNA）`。同一条总结里同一个词只附一次，第二次起直接用中文或缩写。
- 材料里本来就只有英文、且没有通行中文译名的术语（基因名、化合物编号、
  软件名、单位），保留英文原样，不要硬造中文译名。
- 已经通用的英文缩写（DNA、RNA、ATP、Topo II、miRNA）照原样保留。

## 材料里每块的标注怎么读

`〔正文块〕[24597]（p.14）原文：…`

- 方括号里的数字是**块编号**，写 sources 时用它。
- 圆括号里是这个块的**出处**：`p.14` 是第 14 页；
  写成 `p.12-16` 表示这一块**跨了 12 到 16 页**，内容是这几页共有的，
  写 sources 时页码照写 `"12-16"` 这样的区间字符串。
- `〔图片理解·1/2〕[24880]（p.14 图）…` 同理，只是它的文字
  是视觉模型对插图的解读；`1/2` 表示这是同一张图的第几段解读。
- 每页材料开头有一行「【本页在导图中的节点路径】」，告诉你这一页挂在哪个主题下。

## 任务：先判断要不要合并，再写总结

材料给的是**一段连续页**：可能先是若干**上级节点页**（它们在导图里还有下级、自己不
成条，材料被下放到本条），接着是**当前页**，再往后是**后续的末级节点页**。
你要先决定：**从当前页起，连续几页归为一个末级节点**，再为这个节点写一条总结。

**先分清材料里有哪几种页**（页首那行「【本页在导图中的节点路径】」与紧随的注记会写明）：

- **当前页**：user 消息里 `当前页：p.N` 指的那一页，这一条知识点就落在它身上。
- **上级节点页**：页首注记写着 `（注：本页是**上级节点页**「…」……）` 的页。
  它在导图里还有下级节点，**自己不单独成条**，所以它的材料被**下放**到本条。
  - **它的内容必须一并归纳进本条知识点**：不许跳过、不许写"详见上级节点"、
    不许因为它排在当前页前面就当成背景略过。
  - **它的页号必须出现在 `pages` 里**（这些页与当前页连续、排在当前页之前）。
    漏写就等于这些页的内容永久丢失——这正是本版规则要修的那个问题。
- **后续末级节点页**：排在当前页之后的页，按下面的合并规则决定要不要并进来。

**可以合并**（把相邻几页写成**一条**知识点），必须下面两条**同时**成立：
1. **信息密度低**：后面那些页内容明显更少——只有一张图、一句结论、上一页的续写、
   同一张表的续表或重复的标注，单独成条连 3 条要点都写不出来；
2. **主题连续**：和当前页讲的是同一个机制、同一步骤、同一分类或同一结构，
   拆成两条会让读者看不懂前因后果。

**不许合并**（下面任何一条成立就不要合并）：
- 后面那页自己就是一个完整的知识点（有独立的概念、结构、分类或结论）；
- 两页主题不同，属于不同章节、不同药物类别或不同结构层次；
- 只是为了少写几条、让结果看起来更整齐——**减少条数不是合并的理由**；
- 信息不足、拿不准要不要合并——**拿不准就不合并**（宁可多一条，也不要把两件事揉成一条）。

**硬性上下限**：
- `pages` 最少 1 页，必须是**连续页码**、升序，且**必须包含当前页**。
  不许跳过中间页，也不许把不连续的页写在一起。
- 其中**末级节点页最多 3 个**（= 当前页 + 后面合并进来的页）。
  排在当前页**前面的上级节点页不计入这 3 个**，但它们**必须全部写进 `pages`**。
- 上限为什么是 3 个末级节点页：一条总结的正文上限 400 字、要点 3~6 条，而一页课件的
  正文常有 1000~3000 字；三页合起来已经是十倍以上的压缩，再多就只能抄标题、
  提炼不出结构/概念/过程/原因/结果，反而失去"知识点"的意义。

**必须交代合并决策**（这三个字段会被逐条检查）：
- `pages`：这条知识点覆盖的页号列表，升序、连续、含当前页，
  **并含下放给本条的上级节点页**（若有）。
- `merged`：合并了 2 页及以上写 true，只有一页写 false。
- `merge_reason`：**一句话**说明依据，必须点明依据的是"信息密度"还是"连续性"。
  例：`未合并：p.13 有独立的概念定义，信息密度不低`；
  `合并 p.12-p.13：p.13 只有一张结构示意图，与 p.12 同讲碱基互补配对，主题连续且密度低`。

## 要写什么

- **name**：知识点名称，不超过 20 字，用中文。优先用材料第 1 页给出的「节点名」；
  只有在明显不贴合材料时才改写，且改写只能用材料里出现过的词。
  合并了多页时，用能覆盖这几页的**共同主题**命名（仍然只能用材料里的词）。
- **summary**：**连贯的一段话**（不是条目堆叠），150 到 400 字。
  **必须用 3 到 5 句话写完，每句话不超过 80 字**——
  400 字是硬上限，而"句数 × 句长"是你能自己执行的约束（5 × 80 = 400，
  写满也不越界）。按"是什么 → 关键机制/分类/数据 → 意义或用途"的顺序组织。
  **合并了多页时，仍要写成一段把这几页串起来的话**，不要一页一句地罗列。
  **写完后数一遍句号**：超过 5 句就把同类项合并；细节塞不下的挪到 points 里，
  不要靠加长段落解决。
- **points**：**3 到 6 条**要点，每条不超过 40 字。每条都必须是**关键知识点**，
  并且能归入下面五类之一（写作时按这五类挑，不要什么都往里塞）：
  - **结构**：由什么组成、分几类、有哪几部分；
  - **概念**：是什么、术语怎么定义、名字的由来；
  - **过程**：步骤、机制怎么走、先后顺序；
  - **原因**：为什么这样、依据是什么；
  - **结果**：导致什么、有什么后果、用途或意义。
  **禁止**下面三种凑数写法：把 summary 里的一句话截短当成要点；
  把材料里的一句话拆成几个短句凑条数；反复说同一件事。材料只够写 3 条就写 3 条。
- **sources**：出处。page 是页码（跨页块写 `"12-16"` 这样的区间）；
  chunk_ids 是你**实际用到**的块编号（材料里每块方括号里的数字），
  用不到的块不要列；figure_desc 为 true 表示这页的图片理解也被你用上了。

## 禁止原文照录（这条会被机器检查）

- **不许整段粘贴材料原句。** 任何与材料**连续相同超过 20 个汉字**的片段都算照录。
- 必须用你自己的话重新组织：换语序、换连接词、把并列项合并成概括。
- **把材料里的并列短项（图注标签、条目列表）原样串成一句，同样算照录。**
  例：材料里是一串标签「与胰岛素联用 / 低血糖风险 / 促进减重 / 皮下注射每日三次」，
  抄成「与胰岛素联用、低血糖风险、促进减重、皮下注射每日三次」就是照录；
  要改写成有主谓的句子：「图注还标明该药需与胰岛素合用，存在低血糖风险，
  可帮助减重，用法为每日三次皮下注射」。
- **例外**（这些必须与材料逐字一致，不许改写）：药名、化学名、英文缩写、
  数值与单位、必须精确的术语（如"噻唑烷二酮""HbA1c""SGLT-2""拓扑异构酶 II"）。
  例外项本身都很短，不会撞上 20 字上限。

## 必须改写的三类句子（这条比上面更严，逐类自查）

下面三类句子在材料里几乎总是"整句可抄"的，**必须改写，不得原样搬运**：

1. **概念定义句**（材料写"X 是……""X 是指……""X 由……组成"）：
   不要保留材料的定义句式，改写成"X 处在什么位置 / 起什么作用 + 它的组成或
   功能要点"，用你自己的句子结构说同一件事。
2. **实验方法 / 操作步骤句**（材料写"通过……方法""经……处理后""在……条件下"）：
   改写成"用什么手段、达到什么目的、得到什么结果"的概括句；
   步骤可以合并、顺序可以重排，不必逐步复述。
3. **并列清单句**（材料用顿号、分号、换行排出的并列项、图注标签、条目列表）：
   先把同类项合并成几组，再写成有主谓的句子；
   **不许按材料原有顺序把并列项原样串起来**（哪怕换了标点也算照录）。

自查方法：每写完一句，回看材料里有没有**连续 20 个汉字以上**与它完全相同，
有就重写那一句。这三类句子是机器检查的高发区。

## 材料不够就直说

如果材料去重后不足 120 字，或者通篇只有标题、目录、致谢、装饰性内容，
**不要硬写**：把 insufficient 设为 true，summary 写一句话
"材料不足以概括：<原因>"，points 给空数组，pages 与 sources 照常给出你看到的页码。
封面页、提纲页、致谢页、"回顾"页通常属于这一类。
```

## 2. 材料注入格式（`{materials}` 怎么渲染）

窗口内**每页一段**，页内先正文块后识图块，**每块带自己的 chunk_id 与出处**：

```text
===== 第 12 页 =====
【本页在导图中的节点路径】药物化学（Medicinal Chemistry） > 核酸靶点：DNA 与 RNA 的结构与功能 > 脱氧核糖核酸（DNA） > 二级结构：双螺旋 > 复制中磷酸二酯键的形成
〔正文块〕[24597]（p.12）原文：……
〔图片理解·1/2〕[24880]（p.12 图）……
```

- 某页是**上级节点页**（导图里它还有下级、自己不单独成条）时，页首节点路径之后
  紧跟一行注记，`core/kp_build.py` 按"这一页的路径是不是另一页路径的真前缀"判定：
  `（注：本页是**上级节点页**「…」——它在导图里还有下级节点、自己不成条；
  它的内容必须**并入本条知识点**，并在 pages 里带上第 N 页。）`

- 块编号后面圆括号里是**该块自己的出处**（`source_ref`），不是"当前页号"。
  跨页块照它自己的区间写（`p.12-16`），否则模型写出来的出处会指向错误的页。
- `chunks` 表**没有 `page` 列**：页码一律由 `core/kp_build.py` 从 `source_ref`
  （`p.3` / `p.3 图`）解析；解析不到的行**直接拒跑**，不静默丢块。
- 该页 `figure_desc.no_info = 1` 时页首插一行提示
  `（注：本页图片已被判定为"无知识性图示"……）`，避免模型把占位的"无"当成材料。
- **空材料**（该页既无正文块也无识图块）时该页只留表头，并在末尾统一加一行
  `（本次材料为空）`。

## 3. 逐条设计理由

| # | 提示词里的这条 | 为什么必须有 |
|---|---|---|
| 1 | 「材料只有两种」+ 区分正文块/图片理解 | 本项目的立命之本是**可验证**（见 `core/chat.py` 文件头设计要点 4）。正文是原话，图片理解是**含推断的二手解读**，不显式分开，模型会把解读当原文写进知识点，下游再也分不清。 |
| 2 | 「材料里没有的药名/数值/机制…一个字都不许出现」+ 不许按常识补全 | 医药学最容易被模型的先验知识污染。这条把"知识库"与"模型记忆"切干净，也堵住"补全"这种看起来完全正确、却无法用出处核对的注水方式。 |
| 3 | 图片理解与正文冲突时以正文为准 | 与 `core/chat.py` 的 SYSTEM_PROMPT 同一条原则。识图文本读起来极像教科书正文，是本项目实测过的混淆源。 |
| 4 | **全中文 + 专有名词首次附英文**（卡 C-0035 要求 1） | 人要的是"中文为主、术语可检索"。只写中文会让 `Topo II`、`miRNA` 检索不到原文；只写英文则读起来费劲。要求**首次出现**附一次，兼顾可读与可检索；"同一条内只附一次"是防止满篇括号。 |
| 5 | **合并两条件 + 四条负面判据 + "拿不准就不合并"**（要求 2） | 只写"可以合并"必然导致模型为了整齐而乱合。给出"密度低"与"连续性"两条**同时成立**的正向判据，再给出四条负面判据（独立知识点/跨主题/为减少条数/拿不准），把默认值定在"不合并"——**多一条只是冗余，错合一条会让知识点名不副实**。 |
| 6 | **上限 3 页**（要求 2） | 上下限必须可执行。3 页是"一页正文 1000~3000 字 → 总结 400 字 + 要点 3~6 条"这个压缩比下的极限：再合就只剩标题，提炼不出结构/概念/过程/原因/结果。给出理由（不是拍脑袋的数字）模型才会照做。 |
| 7 | **必须输出 `pages` / `merged` / `merge_reason`**（要求 2，可审计） | 合并决策要能被机器与人对账：`pages` 让"这条知识点覆盖了哪几页"可核对，`merge_reason` 一句话说明依据。**不许静默合并**——产物的 `merge_decisions` 一节就是照这三个字段复算出来的（见 `core/kp_build.py`）。 |
| 8 | **points 3~6 条 + 五类（结构/概念/过程/原因/结果）+ 三种凑数写法禁止**（要求 3） | 旧版只限"3~7 条、每条 ≤40 字"，实测模型会把 summary 的一句话截短当要点充数。点名五类等于给了一个**可执行的挑选标准**；点名三种凑数写法等于给出反面样例。条数上限从 7 收到 6，是因为 7 条时最后两条几乎都是重复。 |
| 9 | `summary` 150~400 字 / 3~5 句 / 每句 ≤80 字 | 沿用 C-0031 实测结论：第一轮只写"150 到 400 字"时有 2/3 样本超标（340/497/419 字）——模型数不准字数；改成"句数×句长"后约束变成可执行的（5×80=400）。合并多页时额外要求"写成一段把几页串起来"，防止退化成一页一句的罗列。 |
| 10 | name 优先用节点名、改写只能用材料里的词 | 节点名来自导图（`logs/outline/<doc_id>.json`，模型看过整份课件后给出），带**跨页的结构信息**，比孤立看几页起的名字可靠。禁止自造新词防止知识点名漂移到资料之外。 |
| 11 | 「禁止原文照录：连续相同 >20 汉字」+ 例外清单 | 卡里要求"提炼后的总结，不贴原文"。20 字是**可机器判定的阈值**；药名、术语、数值都远低于它——给例外不会破坏规则。不写例外，模型会为了规避而改写药名，那更糟。 |
| 12 | 「必须改写的三类句子」（沿用 C-0034 逐字） | 概念定义 / 实验方法 / 并列清单这三类在材料里几乎总是"整句可抄"，是机器检查的高发区。点名 + 给出"回看连续 20 汉字"的自查方法，**只收紧、不放宽**。 |
| 13 | insufficient 出口（含"照样要给 pages"） | 封面、提纲、THANK YOU、回顾页本来就没有实质内容。不给出口，模型会把这几个字扩写成 300 字废话——看起来交付了，实际全是水。要求照样给 pages，是为了让"跳过哪些页"在产物里留痕。 |
| 14 | 只输出 JSON + 单行样例（键名与顺序写死） | 沿用 `core/outline.py` 的做法，管线要批量落盘，必须可程序化解析；样例写死键名与顺序，减少字段漂移。 |
| 15 | **上级节点页**的辨识与"必须一并归纳 + 必须写进 pages"（卡 C-0045） | doc#5 实测：旧口径丢 11 页 / 42% 正文，全是"导图里还有下级"的页。只改逻辑不写提示词，模型看到一页排在当前页之前会当成背景略过——`pages` 被管线补上了，总结里却没有它的内容，于是从"整页丢失"退化成"形式覆盖、实质仍丢"。这条与 §「任务」的合并判据配套：**上级页不占 3 个末级页的额度**，所以并不会把总结撑爆。 |

## 4. 成本取向

沿用 `core/outline.py` 的计价方式（非高峰：入 $0.15/1M、出 $0.60/1M、汇率 7.1）：

```
cost_cny = prompt_tokens/1e6*0.15*7.1 + completion_tokens/1e6*0.60*7.1
```

v2 每次调用给的是**最多 3 页**材料（v1 是 1 页），输入随之涨到约 3 倍：
提示词约 2000 token + 三页材料约 1000~6000 token，单次输入 ≈3000~8000 token
≈ ¥0.003~0.0085；输出按 350 token ≈ ¥0.0015。
**单条 ¥0.005~0.01 量级**，一份 75 页课件（合并后约 50~75 次调用）合计约 ¥0.3~0.8。
所以仍然**不需要截断材料**：合并判断本身就要看后面的页，截断会让模型在
"看不见"的情况下猜。

实测数据见 `core/kp_build.py::estimate()`（dry-run 打印的预估）与产物 `meta.cost_cny`。
