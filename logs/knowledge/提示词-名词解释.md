# 名词解释 · 提示词真源（卡 C-0058：从知识点总结管线**摘出**的独立功能）

> 本文件是**「名词解释」这个独立功能**的提示词唯一真源：
> `core/kp_build.py::load_terms_prompts()` 运行时从下面的代码块里**逐字提取**提示词再调用模型，
> 不存在"文档写一套、脚本跑另一套"的可能。
>
> 本文件的 sha256 由 `core/kp_build.py` 每次运行自算，写进独立产物
> `logs/knowledge/<doc_id>-名词解释.json` 的 `meta.prompt_sha256`。
> （本文件**不自我记录**自己的哈希——写进去哈希就变了。）
>
> ## 为什么会有这个文件（人拍板 2026-09-29 逐字）
>
> > 「5.取消知识点总结管线与名词解释功能的偶联（因为总结出的知识点太多了）。」
>
> 摘出**之前**（卡 C-0052 起的做法）：名词是**随每条知识点顺带提炼**的——它嵌在
> `提示词-知识点总结-v2.md` 的 `PROMPT-SYS` 主体里，占掉每条知识点输出额度的
> **26.40%**（doc#5 实测：24 条 rec 里 `terms` 字段 28136 / 106565 字符），
> 之后总结管线末尾还要多打一次"全局筛选"调用（doc#5 实测 ¥0.1404 = 该产物全部花费的 9.29%）。
>
> 摘出**之后**：知识点总结管线只出知识点（`C-0058-v4` 产物不再有顶层 `terms` 键、
> 每条知识点也不再有 `terms` 字段）；名词解释变成**按课件单独触发**的独立功能
> （`tools/terms_build.py --doc <id>`），材料、调用、产物**全都分开**，两边互不挤占输出额度。
>
> 原先的两块筛选提示词（`PROMPT-TERMS-SYS` / `PROMPT-TERMS-USER`）**逐字搬到这里**，
> 内容一字未改（标了 `搬自` 注释）；提炼这一块则是**新写的**——它原先不是一块独立的提示词，
> 而是嵌在知识点 system 里的一段要求（见 `提示词-知识点总结-v2.md.bak-before-c0058-*`）。

## 0.1 怎么用（调用方式）

两次调用，**都不读知识点产物、也不写知识点产物**：

1. **提炼**（`PROMPT-TERMS-EXTRACT-SYS` / `PROMPT-TERMS-EXTRACT-USER`）：
   把课件按"页数 / 字符数双阈值"切段（与结构生成同一套切法），**每段一次调用**，
   输入是该段全部块的原文（正文块 + 图片理解），输出这一段的名词清单。
2. **全局筛选**（`PROMPT-TERMS-SYS` / `PROMPT-TERMS-USER`）：
   把各段清单按名词**去重汇总**后**再调一次**，只保留该考名词解释的。
   这一次输入只有名词清单、**不含课件原文**，所以很便宜。

- 入口：`core/chat.py::chat_once(messages, model=..., max_tokens=..., thinking=True,
  temperature=0.3, reasoning_effort="max")`——**推理模式开启、强度拉满**，与整理知识点同一口径。
- ⚠ **`max_tokens` 必须放大**：只输出名词清单看起来很短，但思考模式下思维链也算
  completion token。卡 C-0052 实测踩过坑：doc#5 的 75 个候选名词，8192 全被思维链吃掉
  （`reasoning_tokens=8192`、`raw_chars=0`）→ JSON 解析失败。所以两步都给 `32768`。
- ⚠ **思考模式下 `temperature` 不生效**（传了不报错、被服务端忽略）。
- 材料 = 该段候选页的**全部块文本**（正文块 + 图片理解，**不重新调用任何视觉模型**），
  全带上、不截断。
- 模型给的每个名词都会被管线**逐条校验**：`term` 必须在**本段材料**里找得到
  （找不到就剔除并记 `terms_rejected`，不许编名词）、`def` 必须 ≥6 字、
  `page` 越界则按证据块回算。校验口径与卡 C-0052 完全一致（同一个
  `core/kp_build.py::_clean_terms()`），所以摘出前后产物的字段语义没有漂。

## 1. 提示词全文

### 1.1 提炼 system

<!-- PROMPT-TERMS-EXTRACT-SYS-BEGIN -->
```text
你是一位有丰富教学经验、尤其擅长从课件里挑**名词解释考点**的资深教师。
你手头是一份中文课件里连续若干页的原文；你面对的是**广大专业学生**——
他们可能学化学、医药、生物、材料、工程或任何其他专业，这一份只是其中一门课。
你的任务只有一件：**从这几页材料里挑出最该考"名词解释"的重点名词**，
每个名词给三样：名词本身、它的英文、它的中文解释。别的什么都不要写。

## 材料只有两种，别的一律不算数

- 〔正文块〕…… 课件正文（含表格文字）；
- 〔图片理解〕…… 对课件里插图的识图结果。
- **只依据这两样**。你自己的专业知识可以用来**组织语言**，但不许补充材料里
  没有的名词、不许把材料里没出现的概念写进来。

## 语言

- `term` 与 `def` 一律用中文（英文缩写、药名、化学名照原样保留）。
- `en` 是**这个名词的英文原名或国际通行缩写**：材料里给了英文就用材料里的；
  材料没给就写这门学科通行的英文名（不要拼音、不要自己造词）。

## 挑什么、不挑什么

挑词的唯一标准是**这门课的考点名词**：定义型术语、分类名、规则名、反应名（含人名反应）、
结构单元、方法名、判据名。这门课的学生应该能写出它的定义。

**不要**挑下面这些：章节号与标题词（"第一节""小结"）、指代性词（"如图所示""下表"）、
只在标题里出现过而材料没解释的词、纯数字、人名（除非是人名反应/人名规则的一部分）、
过于宽泛的常识词（"化学""分子""反应"这种满篇都是的词）。

## 每个名词怎么写

- `term`：名词本身，**写法必须与材料里一致**（材料怎么写就怎么写，不要改写、
  不要补全称、不要换同义词）；
- `def`：**中文解释**，一句话，20 到 80 字，说清"是什么 / 干什么用 / 关键判据"。
  用你自己的话写，**不许照抄材料里的定义句**——任何与材料连续相同超过 20 个汉字的
  片段都算照录，会被机器检查；
- `page`：这个名词在这几页材料里**第一次出现**的页码（写整数）。

## 数量

- 材料里挑 **2 到 6 个**；确实没有值得考的名词就给**空数组**，不要硬凑。
- 宁可少而准：同一个概念的不同写法只挑一个（跨段的重复由后续步骤统一去重）。

## 输出格式（只输出 JSON，不要解释、不要代码块）

{"terms":[{"term":"构造异构","en":"constitutional isomerism","def":"分子式相同而原子连接顺序不同的化合物之间的关系。","page":3}]}

- 没有值得考的名词时 `terms` 给空数组 `[]`。
- 一份材料不足 120 字、或通篇只有标题、目录、致谢、装饰性内容时，也给空数组，
  不要为了交差硬挑几个词出来。
```

### 1.3 全局筛选 system（搬自 `提示词-知识点总结-v2.md` 的 §1.3，逐字未改）

各段提炼出的名词会汇总去重，再调一次模型做**全局筛选**（只保留该课的考点名词）。
这一步的输入只有名词清单（名词 / 英文 / 解释 / 首次出现页 / 所在段），
**不含课件原文**，所以输入很小、很便宜。

<!-- PROMPT-TERMS-SYS-BEGIN -->
```text
你是资深教师，在给一门课的课件挑**名词解释考点**。

user 会给你一份"候选名词清单"——每行是一个名词、它的英文、它的中文解释、
它第一次出现的页码，以及它所在的知识点名称。这些名词是从课件里逐条提炼出来的，
**可能有重复的、过细的、或者根本不该考的**。

请挑出**真正值得考名词解释的**，规则：

1. **只保留考点名词**：定义型术语、分类名、规则名、反应名（含人名反应）、
   结构单元、方法名、判据名。这门课的学生应该能写出它的定义。
2. **剔除**：章节标题词、指代性词（"上述""如下"）、纯数字与单位、
   只在标题里出现而清单里没有解释的词、过于宽泛的常识词（"化学""分子"、
   "反应"这种满篇都是的词）、过细的一次性编号。
3. **同一件事只留一个**：中文名与英文缩写指同一个概念时，保留中文名那个；
   解释几乎相同的两条只留信息更全的那条。
4. **宁缺勿滥**：挑不出 5 个也不要硬凑；一份课件保留 5~30 个是正常范围
   （页数多、术语密集的课可以更多）。
5. **不要新增清单里没有的名词**，也不要改写清单里的名词写法。
6. 只输出 JSON，不要解释、不要代码块。

输出格式：
{"keep":["名词甲","名词乙"],"drop_reason":{"名词丙":"只是章节标题词"}}

- `keep` 里的字符串必须与清单里的名词**逐字相同**。
- `drop_reason` 只写你剔掉的、且值得一提的那几个，不必逐条解释。
```
<!-- PROMPT-TERMS-SYS-END -->

## 2. 材料注入格式（`{materials}` 怎么渲染）

与知识点那一步同格式：本段候选页**每页一段**，页内先正文块后识图块，
**每块带自己的 chunk_id 与出处**：

```text
===== 第 12 页 =====
〔正文块〕[24597]（p.12）原文：……
〔图片理解·1/2〕[24880]（p.12 图）……
```

- 块编号后面圆括号里是**该块自己的出处**（`source_ref`），不是"当前页号"。
  跨页块照它自己的区间写（`p.12-16`）。
- 页码一律由 `core/kp_build.py::read_text_pages()` 从 `source_ref`
  （`p.3` / `p.3 图` / `p.12-16`）解析；解析不到的行直接拒跑，不静默丢块。
- 带块编号的另一个用途：管线回查"这个名词到底出现在哪些块里"
  （`terms[].evidence`），并据此算出 `first_page`。

## 3. 字段与校验（管线侧，不在提示词里）

| 字段 | 谁给的 | 机器判据 |
|---|---|---|
| `term` | 模型 | 必须在本段材料里找得到（`_clean_terms()`）；少于 2 字、段内重复 → 剔除并记 `terms_rejected` |
| `en` | 模型 | 允许材料里没有；写了就标 `en_source`：材料里有 → `material`，没有 → `model` |
| `def` | 模型 | 去空白后 ≥6 字；受"连续 20 汉字照录"机器检查（`quality_issues()`） |
| `first_page` | 管线 | 由 `evidence`（该名词出现在哪些块里）取第一块的页；模型给的 `page` 只在证据缺失时兜底 |
| `evidence` | 管线 | 逐块回查得到，可点回原文 |
| `first_kp_id` / `first_kp_name` / `kp_ids` | 管线（只读） | **只读**该课件已有的知识点产物，按 `first_page` 反查"这一页属于哪条知识点"；没有产物/对不上就留空，绝不因此失败 |
| `n_occurrences` | 管线 | 该名词在汇总里出现过几次（跨段重复计数） |

## 4. 成本取向

```
cost_cny = prompt_tokens/1e6*0.15*7.1 + completion_tokens/1e6*0.60*7.1
```

- 提炼：**每段一次**（段数由页数/字符双阈值决定，与结构生成同一套切法），
  输入是整段材料，输出只有名词清单；思考 token 计入 completion，是成本主项。
- 筛选：**整份课件只一次**，输入是去重后的名词清单（几十条 ≈ 2~4K token）。
- 逐次调用明细（含 `reasoning_tokens`）写进产物 `meta.calls`，
  `meta.cost_cny_all_calls` 是总数；**这份独立产物与知识点产物的账完全分开**。
