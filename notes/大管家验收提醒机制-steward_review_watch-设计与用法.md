# 大管家验收提醒机制（steward_review_watch）设计与用法

# 验收提醒机制：`tools\steward_review_watch.py`

> 人 2026-10-08 要求：「设计验收提醒，在这个验收提醒提醒你之后你就开始检测验收。**验收完毕一次后再次拉起验收提醒**。」
> 本文件是这套机制的**操作手册**。

## 一句话原理

脚本挂成**后台 job** 轮询账本；**发现"有新卡进 review"就立刻退出** —— 退出即产生宿主的
「job 已完成」事件 = **唤醒大管家**。大管家做完预检、人拍板验收后，**重新挂上**脚本，闭环。

```
挂上 → 轮询账本(只读) → 发现新 review → 打印摘要 + exit 0
                                              ↓ 宿主通知
                                     大管家被唤醒 → 亲自预检 → 摆给人拍板
                                              ↓
                                     ★ 验收完再挂上（人明确要求）
```

## 重挂命令（**每次验收完都要做**）

```powershell
& "G:\study_agent\venv\Scripts\python.exe" -X utf8 -u "G:\study_agent\tools\steward_review_watch.py" 60
```

* 用 `run_in_background: true` 挂（会话内后台 job）。
* 第 1 个参数 = 轮询间隔秒（默认 60）。
* **不要加 `--force`**（否则会把"账本里已有的 review 卡"又当新的叫一次；仅当人工想立刻确认现场时才用）。

## 参数

| 参数 | 作用 |
|---|---|
| `[间隔秒]` | 轮询间隔，默认 60；只影响发现延迟，不影响正确性 |
| `--once` | 只检查一轮就退出（调试） |
| `--idle-exit N` | 无新交付跑满 N 秒也退出来叫一次（**默认 3600**；`0` = 关闭该兜底） |
| `--force` | 忽略"已通知"记录：只要账本里有 review 卡就立即唤醒 |

## 退出条件（两者都会唤醒大管家，只是提示语不同）

1. **发现新卡进 review** → `STEWARD-WAKE: NEW-REVIEW N 张卡交付，请立即预检`
2. **空闲兜底** → `STEWARD-WAKE: IDLE N 分钟无新交付，请巡检在跑卡`

## 状态与日志（唯一写入）

* `logs\steward_review_watch.state.json` —— 记录 `notified`（已通知过的卡号），**避免同一张卡反复唤醒**。
* `logs\steward_review_watch.log` —— 每次启动/唤醒/读账本失败都留痕。

## 设计约束与已踩的坑

* **只读账本**；不写账本、不碰项目文件。
* **读不到账本时不退出**，打印错误继续轮询（避免哨兵悄悄死掉）。
* 路径可用环境变量覆盖：`STEWARD_CONSOLE_DIR`（账本目录）、`STEWARD_WATCH_LOGDIR`（状态/日志目录）——**功能测试就靠它**，可在临时账本上验证而不污染真实状态。
* 输出规范：**结论行放最前面**（本项目多次因结论落在输出末尾被截断而误判失败）；明细进日志。
* 文件格式：**必须纯 LF**（项目踩过 CRLF 坑）；`# -*- coding: utf-8 -*-` 必须在**前两行**。
* 它是**事件驱动**的，与已退役的 `steward_wake.py`（秒退 + 看门狗定时唤醒）**语义不同**：人要求的是"交付了就叫我去验收"，不是"每 N 秒叫一次"。
* ⚠ 前任记录过一条教训：**不要用外部守护进程长期代替 DSH job**——守护重启轮询器会让宿主看不到 job 结束，**吞掉唤醒信号**。

## 验证状态（2026-10-08 实测）

* 功能测试（临时账本）：无待验收 → 正确等待；制造 2 张 review → **立即唤醒并退出**、摘要含卡号/标题/交付说明；状态文件正确记录 `notified`。
* 真实闭环：挂上后**当场检测到 C-0067 交付并唤醒**（输出 `STEWARD-WAKE: NEW-REVIEW 1 张卡交付`），完成了第一次真实触发。
