# 交接卡使用协议（长期改进跨会话的"磁盘记忆"）

> 目的：**不依赖对话上下文**。每一个新会话都能在 2 分钟内知道"做到哪、下一步做什么、有什么坑"。
> 配套：`docs/长期改进计划-*.md`（做什么）+ `tools/session_brief.py`（现在在哪）+ `tests/`（什么不能坏）。

## 1. 什么时候必须写交接卡

- 一个任务完成并提交后（建议顺手 `--checkpoint`，补 3 分钟）；
- **上下文用到一半**（明显感觉记不住前面细节时）→ 立刻停手写卡，换新会话继续；
- 一次会话结束前（不管任务做没做完）；
- 做了重要决策（选型、放弃某方案、踩到权限/费用限制）之后。

## 2. 交接卡里必须有什么

| 节 | 内容 | 写法要求 |
|---|---|---|
| 2. 本次做了什么 | 改了哪些文件/提交号 | 一句话一条，带 `git show` 能对上的提交号 |
| 3. 没做完 / 下一步 | 可执行动作 | 写"改哪个文件、加哪个入口、验收命令"，不写"继续优化" |
| 4. 关键决策与理由 | 为什么这么选 | 写"为什么"（评审会忘的就是理由，不是结果） |
| 5. 踩坑与注意 | 复现命令/规避方式 | 比如"沙箱要复制 logs/knowledge 才能测批量整理" |
| 6. 证据位置 | 截图/报告/API 输出路径 | 让下一会话不必重跑 |

第 1 节（git/服务/计划进度）由 `tools/session_brief.py --checkpoint` 自动采集，不要手改。

## 3. 新会话开场三步（固定动作）

```powershell
cd D:\study_agent
venv\Scripts\python.exe -X utf8 tools\session_brief.py      # ① 看简报（含最新交接卡）
venv\Scripts\python.exe -X utf8 tools\healthcheck.py        # ② 确认环境/数据/看板/MCP
git status --short                                          # ③ 确认没有别人的半成品
```

然后把 `docs/长期改进计划` 状态表里的下一个任务领走；一次会话**只做 1–2 个任务**，做完就更新状态表 + 提交 + 写交接卡。

## 4. 文件命名与保留

- 命名：`docs/交接/YYYY-MM-DD-HHMM-<head7>.md`（`--checkpoint` 自动生成）；
- 保留最近 20 张，更早的合并进季度归档（`docs/交接/archive/`），不要删——它们是项目的"事故与决策史"。

## 5. 记忆的优先级（出问题时按这个顺序信）

1. **测试**（`tests/run_all.py` 全绿 = 行为没坏；比任何文档可信）；
2. **git 历史 + 当前 diff**（真实发生过什么）；
3. **交接卡 + 计划状态表**（人的判断与下一步）；
4. 代码注释与 docs；
5. 对话上下文（随时可能被压缩，**不要**当作唯一依据）。

## 6. 和子智能体的配合

长任务尽量拆给子智能体（每个子任务上下文短、产出写文件）；主会话只保留**决策 + 验收 + 交接**。
子智能体的产出必须落到 `_work/` 或 `docs/` 文件里，否则会话结束就消失了。
