## 0. 三条铁律

1. **不动真实数据**：`raw/`、`index/`、`subjects/`、`notes/`、`logs/`、`models/`、`.env`
   是用户数据/密钥。开发与测试只用副本（`_work/` 下），真实看板 8756 正在使用时也不要重启它。
2. **改完必须验证**：先跑 `tools/healthcheck.py`（快速健康），再跑 `tests/run_all.py`
   （隔离验收套件）。没有验证证据的改动不算完成。
3. **小步提交**：一个逻辑改动一个 commit；不要 `git add -A` 把别人的半成品卷进去。

## 5. 写代码时的项目约定（踩过的坑）

- **编码**：`.cmd`/`.ps1` 必须纯 ASCII（cmd.exe 按 GBK 解析，中文注释会被误读成命令）；
  `.py` 用 UTF-8；行尾不要批量改动。
- **stdout 纪律**：MCP 服务的 stdout 是 JSON-RPC 协议通道，日志只能走 stderr。
- **错误处理**：Web API 非法入参用 `_int_arg()` 兜底或返回 4xx JSON，不要抛 500。
- **路径**：启动脚本一律用 `%~dp0` 相对定位，不要硬编码盘符（G:→D: 的教训）。
- **签名/参数**：`core/` 的函数签名就是契约；`tools/serve_mcp.py` 等适配层改了要跑 MCP 握手。
- **恢复版代码**：`core/search.py` 是 AI 重建版（v1.1 真值 32 个函数缺 13 个），
  `core/kp_build.py` 有 3 处 `TODO(反编译存疑)`，`core/study.py`/`kp_batch.py` 有重建改写——
  改这些模块要格外小心，先看 `docs/audit/` 里的审计结论。
