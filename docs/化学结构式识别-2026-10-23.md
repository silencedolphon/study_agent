# 化学结构式 / 图形资料识别方案讨论（2026-10-23）

> 背景：用户指出 PPT 里的化学结构式本来可以用文字层/矢量对象表达，但 OCR/识图把它当普通图片，
> 识别不出真正的结构式，信息丢失。若靠"所有课件逐页识图"解决，费用与时间都高。
> 本文只做方案分析与成本测算，**不涉及本轮代码改动**。

## 1. 现场盘点（本机真实数据）

| 项 | 实测 |
|---|---|
| 课件 | 9 份 `role=courseware`，全是 PPT（5 份有 `.ppt` + `.pptx` 双份，4 份 `.pptx`） |
| 文本层规模 | 每份 2.2k–12.4k 字符（chunks 17–78 块）——相对页数明显偏少，说明大量内容在图形/结构式里 |
| 已缓存的整页图 | `logs/figure_desc/<deck>/slide_*.png`：**9 份、共 462 张、约 132 MB**（入库时已经渲染过，无需再渲染） |
| 已有识图产物 | 部分页有 `slide_*.md` 描述（通用识图 prompt：讲"这页画了什么"，不是"结构式是什么"） |
| 教材 | doc#50 药理学第6版 538 MB / 452 页扫描件，靠识图文本入库 |

**关键结论**：真正贵的是"视觉模型调用次数"，不是渲染；而整页图已经全部缓存，所以
"只对结构式页补识图"在工程上可行，成本也可控——不需要重新渲染 462 页。

## 2. 信息是在哪一步丢的

1. PPTX 的正文文字层：当前入库只取到一部分文本（标题/正文框），
   **组合形状（group）、矢量自选图形、OLE/ChemDraw 对象里的文字**可能没抽全；
2. 结构式多为**矢量线条 + 原子标签**（C/N/O 环、双键、箭头），文字层里可能只有零散原子符号，
   语义上不可还原；
3. 通用识图模型能说"图中有一个苯环和取代基"，但**不保证给出可核对的完整结构**；
   若它把取代基位置说错，后面的知识点总结会被带偏（本轮提示词已加"写后自检 + audit"缓解，
   但没有从源头补结构信息）。

## 3. 可选的解决路线

### A. 先榨干文字层（0 AI 成本，建议必做）
- 用 PPTX 的 XML 直接扫描**所有 `<a:t>` 文本节点**（不只顶层 shape），把组合形状、
  表格、备注中的文字都抽出来；对 `.ppt` 用现有的 LibreOffice/转换链先转 `.pptx`。
- 能救回"用文本框写的结构式/反应式/命名/分子式"（例如 `C6H12O6`、`2H2O2 → 2H2O + O2`）。
- 救不回"纯线条画的结构"；但这一步 **¥0、几分钟**，且不改现有识别管线，先做不亏。

### B. 结构页选择性识图（推荐 MVP，成本可控）
- **不逐页识图**，先用启发式只挑"疑似结构/图形页"：
  * PPTX XML：自选图形/连接线/组合形状数量多、文字很少；
  * 页图上直线/箭头/环状轮廓多、文字像素少（可用简单图像统计，不必上大模型）；
  * 关键词：结构式、合成、反应、构效关系、母核、取代、R 基、手性；
  * 有嵌入图片/OLE/ChemDraw 对象。
- 只对挑中的页调 **专用结构式识图 prompt**（可复用现有视觉模型，一张一次）：
  要求"用文字描述结构：母核、取代基及位置、官能团、立体化学；能确定就给 SMILES，
  不能确定标 uncertain；禁止猜"。
- 产物单独存 `logs/knowledge/<doc>-结构页.json`（页号、结构描述、SMILES?、置信度、
  原图路径），作为知识点管线的**旁证材料**，不直接当正文；KP 窗口显示"结构式原图"入口。
- 估算：462 张里按 10–20% 计 → **46–92 次视觉调用**；按单图 ¥0.003–0.01 估
  **¥0.2–0.9 一次性**；并发下 **1–3 分钟**。对比全量 462 张约 ¥1.4–4.6、5–15 分钟，
  省 70–90% 调用。

### C. 本地化学结构识别（OCSR，0 API 费用，可选）
- 开源方案：MolScribe、DECIMER、OSRA、Imago 等；对干净单结构式准确率尚可，
  对反应式/多结构/手绘箭头容易失败。
- 优点：无按次费用、可离线；缺点：需装环境/模型权重、CPU 慢、准确率不保证；
  建议只在"结构页"上跑，并与 B 的结果交叉校验，而不是全量替代。

### D. 矢量导出 + 解析（高保真但工程量大）
- `LibreOffice --convert-to svg` 或 `pdf` 后解析矢量线段/文字，重建原子-键图；
  对规则结构式可行，但遇到 ChemDraw OLE、渐变、手绘曲线会很复杂。
- 不建议作为 MVP；可作为后续"高精度模式"。

### E. 人在环（最便宜、最可靠，建议与 B 同步做）
- 对所有"结构页"在知识点窗口/原文出处里提供**原图缩略图 + 打开整页**；
  结构式是否看错由人一眼判断，不需要模型 100% 正确。
- 现有 `/img/slide` 已经能出整页 PNG、KP 窗口也有出处链接，扩展成本低。

## 4. 推荐组合

**A（文字层全量抽取，¥0）+ B（结构页选择性识图，¥0.2–0.9/全库）+ E（原图人工核对入口）**
- 先做 A：免费，立刻补回一部分"文本形式的结构式"；
- 用 B 的启发式筛出结构页，只对筛中的页跑专用 prompt；结果标置信度、存独立产物；
- E 保证"模型没看对"时用户能 1 秒核对原图；
- C 作为后续增强（在结构页上本地 OCSR，与 B 交叉），D 暂不做。

**为什么不做"所有课件逐页识图"**：462 页全量一次约 ¥1.4–4.6、5–15 分钟；
而结构页通常只占 10–20%，且整页图已缓存，选择性识图能把成本压到 **¥0.2–0.9**，
同时不牺牲文字层已有信息。真正需要全量识图的只有"扫描版教材"，那是另一条线。

## 5. 落地步骤（后续任务，非本轮）

1. `tools/structure_scan.py`：扫 PPTX XML/页图特征，输出 `<doc>-结构页.json`（页号+理由+关键词）；
2. 新提示词 `logs/knowledge/提示词-结构式识图.md`（结构描述/SMILES/uncertain 规则）；
3. 入库/整理时只对筛中页补识图，结果写独立产物，不混入正文块；
4. KP 窗口/原文出处显示结构页缩略图 + "打开结构原图"；
5. 评估：拿 1 份课件人工标注 10 页，算结构页召回/精度与识图描述可用率，再决定是否扩到全库；
6. 若准确率不够，再上 C（本地 OCSR）做第二意见，而不是加钱全量识图。

## 6. 风险与注意

- 视觉模型对结构式的"描述"仍是自然语言，不能保证化学正确；必须标 uncertain 并保留原图；
- SMILES 生成错误比"没生成"更危险 → prompt 要求"不确定就不输出 SMILES"；
- 结构页筛选有漏检/误检，需人工抽检；建议先在一份课件上验证再全库跑；
- 不要把结构描述直接写进知识点正文而不带"来源可疑"标记；本轮 KP 提示词的 `audit.source_suspects`
  正好可以承接这类信息。
