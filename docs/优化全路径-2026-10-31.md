### S01 RunContext：固定每次运行的配置/学科/路径

**问题**：`core/config.py::activate()` 会改写 `chat` 模块全局端点/模型/环境变量；部分路径依赖线程本地或全局回退值。
多条管线/多学科并行时可能串用设置。

**改动**
- 新建 `core/pipeline_runtime/context.py`：
  ```python
  @dataclass(frozen=True)
  class RunContext:
      run_id: str
      pipeline: str
      subject_id: str
      db_path: Path
      log_dir: Path
      model: str
      api_base: str
      thinking: bool
      reasoning_effort: str | None
      max_tokens: int          # 0 保持“不发送 max_tokens”语义
      prompt_version: str
      schema_version: str
      credential_ref: str      # 只存引用，不存密钥正文
  ```
- `make_context(pipeline, subject=None, doc_id=None)` 在任务入口**取一次**实际设置；
- 子线程/线程池显式传 `RunContext`，不能依赖 `threading.local` 自动传播；
- `chat.chat_once/stream_chat`、`figures._http_post`、`kp_build/preview/teach/textbook_kp/structures` 增加可选的 `context` 参数；
- 旧调用路径默认从当前 `config.activate()` 兼容取一次上下文，逐步替换；
- `config.activate` 保留为兼容 shim，但运行期间不再让它改写其它管线已固定的上下文。

**验收**
- `tests/test_37_run_context_isolation.py`：
  - 两个线程分别绑定 `model/base/max_tokens/subject/db_path` 不同的上下文；
  - 捕获实际发出的请求参数/DB 路径，断言各自一致、零串用；
  - 一个管线报错不影响另一个。
- 旧测试全绿；真实 8757 不做并发付费测试。

**回退**：`PIPELINE_RUNTIME=0` 使用旧全局路径；默认先只对教材知识点/预习启用。

### S03 remote_unknown / 去重 / 单飞

**问题**：超时后远端可能仍成功/计费；当前部分路径可能把超时当失败自动重试，造成重复付费。

**改动**
- 新建 `core/pipeline_runtime/state.py`：
  ```text
  planned → running → done / failed / partial / cancelled / remote_unknown
  ```
- 每个付费调用记录：`call_id, started_at, timeout, finish_reason, usage_if_known, request_meta(无密钥), status`。
- 超时/断线：标 `remote_unknown`；**不自动重发同一付费请求**；进度/界面明确“远端未决，需确认”；
- 若服务商支持请求查询/幂等，按实际能力核对；不能假设 OpenAI 兼容端点都支持；
- single-flight：同 subject + doc + stage 用 SQLite UNIQUE 或文件锁；学科隔离；锁过期/恢复策略；
- 释放本地槽位不等于远端停止：单独未决计数；达到上限暂停新付费调用。

**验收**
- 假模型注入超时：状态为 `remote_unknown`，没有第二次网络请求，old progress 接口仍可读；
- 两个线程同 doc/stage 只执行一次；
- `tests/test_39_remote_unknown.py`。

**回退**：旧重试开关；未知状态只记录不拦截（先观测一天再启用拦截）。

- 分段从“16,000 字符硬切”改为“节 → 标题 → 段落 → 最后按长度”；
- 保留 chunk ID/页码/字符区间；超长自然段允许少量重叠并按来源去重；
- JSON 失败：有效点存本地暂存并标 `partial`，不冒充 done；严重截断停止，不自动再调用“修 JSON”；
- 复习记录：旧点 ID 保留；新旧按来源范围/标题/内容做唯一匹配迁移；歧义不合并；
- 验收：`tests/test_44_textbook_partial_migration.py`；至少测试“已记住/到期日/来源窗口/跨章隔离”。

### S11 课件知识点：节点缓存与页面归属

- 结构/知识点两阶段分别缓存；
- 节点级输入指纹：材料、页图/图注、提示词、实际模型/推理/上限；
- 保留 `claim_pages/release_pages`；验证无双重占用、无漏页、失败节点可释放续跑；
- 完全相同文本去重；模糊相似默认不启用；
- 小节点合并只做**离线实验**，不默认开启；
- `persist()` 若实测为瓶颈，改按节点增量记录 + 定期合并，最终仍输出旧 JSON，不删除断点保护。

### S12 崩溃恢复与跨文件/DB

- 设计“预备结果 → 校验 → 切换”：SQLite 与页图/JSON 无跨介质原子事务；
- 写意图/版本清单 + 启动恢复；注入断电/进程 kill 测试；
- 仅在结果就绪后短事务写 DB；远程/ONNX/COM 不放在写事务内；
- 旧数据库/索引/产物关系保持一致；分享/删除/笔记引用不受影响。

**验收**：fake 断电/中断注入后旧成果可读、无半截索引、无重复付费。

## 5. P3：质量与结构（需要样本评估，不能只追速度）

### S13 长章完整覆盖

- 覆盖统计可复算：总页/块、进入模型的页/块、图片理解块、明确遗漏 ID；
- 超长章按节分段，先段级证据再合并；普通章保持单次调用；
- 任何截断记录确切页/块；不能把被裁剪内容算作已总结；
- 先离线样本对照，真实模型效果需用户授权小样本。

### S14 课件知识点节点粒度实验

- 相邻小节点合并只作为实验；比较知识覆盖、引用、实际花费；
- 默认沿用现有粒度；用户接受后才改默认；
- 不为了少发请求删知识点。

### S15 复习记录/旧产物迁移

- 教材知识点点 ID 因分段变化可能变化；
- 先保留旧 `.review.json`；自动迁移只对可证明唯一匹配；
- 歧义保留为未合并，提供人工/明确流程；
- 测试“已记住、到期日、来源窗口、跨章隔离”。

### S16 模块拆分

- 不一次性搬空 `kp_build.py`；先编排外壳、纯函数、最后替换调用点；
- 每步用现有行为测试和产物样本对比；
- 同名常量/重复定义先确认 Python 最后生效定义与旧入口，再删真正无引用部分。

## 7. 基准、验收与门禁

### 7.1 每阶段必须提供的证据

- 全量测试/矩阵/healthcheck；

- 真实数据零写入（指纹对比）；
- 失败/超时/崩溃的注入测试。

## 9. 建议工作量与顺序

| 阶段 | 内容 | 估算（单人工作日） |
|---|---|---:|
| P0 | S00–S04 基线/上下文/计时/unknown/并发 | 3–4 |
| P1 | S05–S08 解析复用/页图缓存/向量/章材料 | 4–6 |
| P2 | S09–S12 阶段缓存/教材 partial/课件节点/恢复 | 5–8 |
| P3 | S13–S16 长章/粒度/迁移/拆分 | 5–10 |
| P4 | S17 Agent | 2–4 |
| 验收 | S18 全量 + 真实/假模型样本 | 2–3 |

合计约 **3–5 周**（不含用户等待/真实付费模型排队）。先完成 P0 + P1 再决定是否值得继续 P2/P3。

**停止条件**：

- P0 出现无法解释的配置串用/重复调用 → 停止，先修可靠性；
- P1 热缓存没有可测收益 → 停止该子项，不强行上 P2；
- P2 迁移无法保证旧复习记录/旧产物 → 停止迁移，保留旧读取；
- P3 质量下降 → 回退默认旧粒度/旧提示词；
- 任何付费测试超预算或输出不可核对 → 立即停止。

## 10. 最终“完成”的定义

同时满足以下条件才算完整优化：

1. 全量测试 + 矩阵全绿；healthcheck PASS；
2. 同一输入、同一设置下，核心产物/API 字段/页图/复习记录与旧版兼容；
3. 冷/热/失败/恢复/并发/超时六类基准均有数据；
4. 无真实数据被基准/测试写入；无密钥进入日志/缓存；
5. 旧缓存/旧产物不会被自动付费重跑；
6. 付费测试有记录，费用可解释；
7. 每个新路径都有独立回退开关；
8. 不宣称“整体一定更快”——只报告实际测量的阶段收益和边界。
