## 0A. v2 修订说明（按 GPT 审阅意见）

GPT 对上一版方案做了只读审阅和临时样本测试，指出 **3 个现有代码缺陷** 和 **6 处规划问题**。
v2 已把它们前置，而不是继续按原计划做缓存：

### 0A.1 先修三个可复现缺陷（新增 S00A）

1. **教材知识点快速查询漏章节**
   - 现实现 `core/textbook_kp.py` 的快速路径只 `LIKE '%第N章%'`；
   - 正式解析允许 `第1章`、`第 1 章`、`第01章`；同一章混用这些格式时，快速路径可能只取部分块，
     且有命中时不会回退整表；
   - 临时样本：快速路径 1 块，旧路径 3 块。
2. **预习快速路径静默跳过无有效页码的块**
   - `core/preview.py` 的章节聚合先 `continue` 掉 `_parse_ref` 失败的块；
   - 旧路径 `read_text_pages` 会明确报错“页码解析不出，拒绝静默丢块”；快速路径看不到这些块，
     可能把不完整的章当完整。
3. **课件知识点页面预约键不一致**
   - `core/kp_build.py::claim_pages` 读取用 `claimed.get(_n)`，写入却是 `claimed[str(kp_id), _n]`；
   - A/B 同一页可同时“预约成功”；`release_pages` 又按 `claimed.get(_n)` 查，三处结构不一致；
   - 已有最终重叠检查，不会必然产生重复知识点，但冲突可能拖到模型调用后才暴露，浪费费用/时间。

**v2 的硬规矩：S00A 三项修复与测试完成前，不得把现有快速路径当作可靠基线。**
生产上建议先设：

```text
PREVIEW_CHAPTER_FAST=0
TEXTBOOK_KP_FAST_PLAN=0
```

等 S00A 修复并用混合格式/坏页码样本证明安全后，再恢复默认快速路径。

### 0A.2 六处规划修正

1. **章节缓存不能看 DB 文件 mtime/size**：项目使用 SQLite WAL，主文件可能不变而 WAL 已有提交；
   改为“与数据写入同事务的 revision”，或对实际读取的 chunk 记录行级指纹；`PRAGMA data_version`
   只能辅助检测连接内变化，不能当全局版本号。
2. **删除“unknown 先观察一天”**：从机制启用起，“请求可能已发出但结果未知”就禁止自动重发；
   只有发生在发送之前的错误（参数校验、无密钥、连接建立失败）按普通失败处理。费用未知记 unknown，不记 0。
3. **RunContext 必须贯穿发送请求**：仅新增上下文不够；`chat.py` 发送时仍会重新读 token 设置，
   其它路径可能读全局端点/环境变量；测试要覆盖运行中改设置、不同学科并行、流式请求、识图请求。
   回退旧全局路径时**不能声称已保证隔离**。
4. **一次解析要保持 OCR 前后口径**：入库会把 OCR 内容追加到提取结果；当前识图路径会重新提取原始页面文本。
   直接把追加后的结果传给识图可能改变视觉上下文；验收必须比较**实际发送给视觉模型的上下文与参数**，
   不能只比较 chunks。
5. **分段与复习迁移放在同一质量阶段**：教材分段会改变模型输入、知识点 ID、复习记录；
   不能 P2 先改分段、P3 才做迁移。三者（旧记录保护、来源覆盖验证、费用估算）必须同一门禁一起验收。
6. **单飞锁粒度细化**：不能只用“学科 + 文档 + 阶段”；至少加入 chapter/page/KP/请求指纹/配置指纹，
   并允许用户主动 force 重做；锁过期、释放、恢复要可测。

### 0A.3 速度判断维持保守

GPT 同意：真实跑批中本地章节读取只省十几毫秒，课件总结/预习/教材总结是百秒级；
没有公平新旧全流程对照，**不能宣称整体已明显加速**。下一步最值得测的是
**识图/页图缓存、模型调用实际耗时与重试**；不能为了快盲目过滤图页或减少知识覆盖。

### S00A 先修三个可复现缺陷（最高优先级）

> 这三项不是“优化”，是现有代码/上一版快速路径的安全问题；S00A 完成前不做 P1/P2。
> 修复过程零模型调用，使用临时 DB/假数据；真实 `index/study.db` 只读。

#### S00A-1 教材知识点章号格式漏块

**问题**：`textbook_kp._plan()` 的快速查询只匹配 `%第N章%`，而正式解析允许 `第 1 章`、`第01章`；
同一章混用时快速路径只取命中格式的块，且因 rows 非空不触发整表回退。

**改法**
1. 只读轻量元数据：`SELECT id, heading_path FROM chunks WHERE doc_id=?`（不取正文）；
2. 用**现有正式正则/归一化函数**解析每个 `heading_path` 的章号；统一 `第N章`、`第 N 章`、`第0N章`；
3. 选出本章所有 block id，再 `SELECT id, ord, source_ref, text ... WHERE id IN (...)` 取正文；
4. 若元数据里有无法解析/歧义行，**回退慢路径**并记录原因；不能“rows 非空就算命中”；
5. 新增测试样本：同一章混用三种格式 + 空白章号；断言 fast/slow 的 selected blocks、signature、chars 完全一致；
6. 真实 doc50 42 章只读抽查 compare fast/slow signature。

**验收**：临时混合格式样本 fast 与 slow 输出逐字一致；不再出现 1 块 vs 3 块。

#### S00A-2 预习快速路径静默丢坏页码块

**问题**：`preview.list_chapters()` 聚合时先 `continue` 掉 `_parse_ref` 失败的块；
快速路径看不到这些块；旧 `read_text_pages()` 会明确报错（拒绝静默丢块）。

**改法**
1. `list_chapters()` 不要把坏块当不存在：记录 `invalid_refs`（块 id/source_ref）并在章节对象/顶层返回；
2. 快速路径 `read_chapter_ch()` 检测到本章/全库存在坏页码块时：
   - 优先回退 `_read_chapter_ch_slow()`，让旧路径抛出同语义错误；或
   - 直接抛出与 `read_text_pages` 一致的可操作错误；
   不能返回“少块但成功”的材料；
3. 若以后支持“页码未知”的来源，另立 schema/版本，不混进当前完整章；
4. 测试：一章两块、其中一块 `p.xxx` 坏；断言 fast/slow 都失败且错误一致；无坏块时 fast/slow 输出一致。

**验收**：坏页码样本不再静默成功；旧行为不被“快速”绕过。

#### S00A-3 课件知识点页面预约键统一

**问题**：`kp_build.claim_pages` 读取 `claimed.get(_n)`，写入 `claimed[str(kp_id), _n]`；
`release_pages` 按 `claimed.get(_n)` 查。三处结构不一致；A/B 可同时预约同一页。

**改法**
1. 统一为 **`dict[int, str] = {page: owner_kp_id}`**（或明确 dataclass `PageClaims`）；
2. `claim_pages`：先查 `claimed.get(page)`；无主/同主才写入 `claimed[page] = kp_id`；
3. `release_pages`：仅当 `claimed.get(page) == kp_id` 才 pop；
4. 检查初始化/续跑恢复/结果收敛/失败回滚/最终重叠检查（`kp_build.py` 约 5330 附近）
   全部使用同一结构；旧代码若持久化过不同形状，读取时做一次性兼容转换；
5. 测试（零模型）：
   - A 预约 p.5 → 成功；B 预约 p.5 → 返回空/不成功；A 释放 → B 可预约；
   - 同 owner 重复预约幂等；
   - 中途失败全部释放；续跑恢复后预约状态一致；
   - 并发 A/B 同一页只有一个成功；最终 overlap 检查仍兜底。
6. 不加“先到先得”之外的新策略；用户主动 force 重做不受旧预约残留影响。

**验收**：`tests/test_00a_known_defects.py` 全绿；真实课件正常任务重叠检查仍为 0；不真实调模型。

**完成 S00A 后**：重新跑全量/矩阵；把 `PREVIEW_CHAPTER_FAST`、`TEXTBOOK_KP_FAST_PLAN`
默认恢复为 1 前，先用混合格式/坏页码/预约并发样本证明安全。

### S01 RunContext：固定每次运行的配置/学科/路径

**问题**：`core/config.py::activate()` 会改写 `chat` 模块全局端点/模型/环境变量；部分路径依赖线程本地或全局回退值。
多条管线/多学科并行时可能串用设置。

**改动**
- 新建 `core/pipeline_runtime/context.py`：
  ```python
  @dataclass(frozen=True)
  class RunContext:
      run_id: str
      pipeline: str
      subject_id: str
      db_path: Path
      log_dir: Path
      model: str
      api_base: str
      thinking: bool
      reasoning_effort: str | None
      max_tokens: int          # 0 保持“不发送 max_tokens”语义
      prompt_version: str
      schema_version: str
      credential_ref: str      # 只存引用，不存密钥正文
  ```
- `make_context(pipeline, subject=None, doc_id=None)` 在任务入口**取一次**实际设置（模型/端点/推理/上限/凭据引用）；
- 子线程/线程池显式传 `RunContext`，不能依赖 `threading.local` 自动传播；
- **真正贯穿发送**：
  - `chat.chat_once/stream_chat` 发送 payload 时不得再调用 `config.token_cap()` / 重新读当前管线设置；
  - `figures._http_post`、结构式/识图、`preview`、`kp_build`、`teach`、`textbook_kp` 全部使用传入 context 的 model/base/thinking/effort/max_tokens；
  - 凭据只在发送时按 `credential_ref` 取，不写缓存/日志；
  - 流式请求与识图请求同样走 context；不能只覆盖非流式 chat；
- 旧调用路径默认从当前 `config.activate()` 兼容取一次上下文，逐步替换；
- `config.activate` 保留为兼容 shim，但运行期间不再让它改写其它管线已固定的上下文。

**验收**（`tests/test_37_run_context_isolation.py`）
- 两个线程分别绑定 `model/base/max_tokens/subject/db_path` 不同的上下文；捕获实际 HTTP payload/DB 路径；
- 任务**运行中切换设置**：已启动任务继续用旧快照，新任务用新快照；
- 不同学科并行：DB/日志路径不串；
- 流式请求与识图请求：各自捕获请求，模型/端点/图片内容不串；
- 一个管线报错不影响另一个；
- **回退 `PIPELINE_RUNTIME=0` 时明确标记“旧全局路径，不保证隔离”**，测试不能把回退模式算成隔离通过。

**回退**：`PIPELINE_RUNTIME=0` 使用旧全局路径；默认先只对教材知识点/预习启用。

### S03 remote_unknown / 去重 / 单飞

**问题**：超时后远端可能仍成功/计费；当前部分路径可能把超时当失败自动重试，造成重复付费。

**改动**
- 新建 `core/pipeline_runtime/state.py`：
  ```text
  planned → running → done / failed / partial / cancelled / remote_unknown
  ```
- 每个付费调用记录：`call_id, started_at, timeout, finish_reason, usage_if_known, request_meta(无密钥), status`。
- 超时/断线：标 `remote_unknown`；**从机制启用起就不自动重发同一付费请求**；
  进度/界面明确“远端未决，需确认”；
- 只有**发送之前**发生的错误（参数校验、无密钥、连接建立失败）才按普通失败处理，可安全重试；
- 若服务商支持请求查询/幂等，按实际能力核对；不能假设 OpenAI 兼容端点都支持；
- single-flight 键不能只有“subject + doc + stage”；应包含：
  `pipeline + subject + doc_id + stage + chapter/page/KP 或请求对象 + 实际配置/提示词指纹`；
  学科隔离；锁过期/恢复策略；用户主动 `force` 重做可以绕过旧锁但必须显式标记；
- 释放本地槽位不等于远端停止：单独未决计数；达到上限暂停新付费调用。

**验收**
- 假模型注入超时：状态为 `remote_unknown`，没有第二次网络请求，old progress 接口仍可读；
- 两个线程同对象/同配置只执行一次；不同 chapter/page/KP/配置可并行；
- 用户 force 重做能绕过已完成锁，但不会与正在执行的同对象任务并行；
- `tests/test_39_remote_unknown.py`。

**回退**：只允许回退到“普通网络失败重试”的旧行为；**不得回退到“远端未知也自动重发”**。
一旦检测到请求已发出但结果未知，停止自动重发，费用记 unknown。

### S08 预习/教材章节材料缓存

### 7.3 付费测试规则

- 优先 fake/replay 响应；
- 任何真实模型测试必须提前说明：样本、调用次数、费用上界、是否双跑；
- 不得用影子流量偷偷产生额外费用；
- 旧缓存/旧产物不得因“升级”自动触发付费重跑；
- 真实跑批结果要同时记录输入材料 hash/签名，否则无法区分“代码变了”还是“模型随机了”。

## 8. 回退策略总表

| 阶段 | 开关/回退 |
|---|---|
| RunContext | `PIPELINE_RUNTIME=0` 回旧全局路径 |
| 计时 | `RUNTIME_TELEMETRY=0` 只写旧 meta |
| unknown/single-flight | 普通发送前失败可重试；**发送后未知禁止自动重发**；不能回退到“未知也重发” |
| 入库复用 | `INGEST_REUSE_EXTRACT=0` |
| 页图缓存 | `FIGURE_CACHE_V2=0`；旧目录只读兼容 |
| 向量复用 | `EMBED_REUSE=0` |
| 章材料缓存 | `MATERIAL_CACHE=0`；`PREVIEW_CHAPTER_FAST=0`（已存在） |
| 教材 plan | `TEXTBOOK_KP_FAST_PLAN=0`（已存在） |

所有涉及数据库/产物迁移的步骤：先在副本演练恢复，**不覆盖用户笔记/历史复习记录**；每个阶段可独立停止/回退。

## 9. 建议工作量与顺序

| 阶段 | 内容 | 估算（单人工作日） |
|---|---|---:|
| S00A | 三个缺陷修复 + 混合格式/坏页码/预约测试 | 2–3 |
| P0 | S01–S04B 上下文/计时/unknown/并发/资源 | 3–4 |
| P1 | S05–S08B 解析复用/页图缓存/向量/章材料/其他管线 | 4–6 |
| P2 | S09–S12 阶段缓存/教材 partial/课件节点/恢复 | 5–8 |
| P3 | S13–S16 长章/S13B 分段与迁移/粒度/拆分 | 6–10 |
| P4 | S17 Agent | 2–4 |
| 验收 | S18 全量 + 真实/假模型样本 | 2–3 |

合计约 **4–6 周**（不含用户等待/真实付费模型排队）。
**先完成 S00A + P0 + P1 的测量**，再决定是否值得继续 P2/P3；不要为了“进度”跳过测量。

**L1 优先测量项（P1 内）**

1. 识图/页图缓存能减少多少渲染/视觉调用；
2. 每次模型调用的实际 `queue_ms/work_ms`、重试次数、finish_reason；
3. 二次入库/重复章节的热缓存收益；
4. 不要为了提速盲目过滤图页或减少知识覆盖。

**停止条件**：

- S00A 有一个缺陷未修完/未补回归 → 停止，不允许继续缓存或分段；
- P0 出现无法解释的配置串用/重复调用 → 停止，先修可靠性；
- 回退 `PIPELINE_RUNTIME=0` 时仍声称隔离 → 停止，修正文案/测试；
- P1 热缓存没有可测收益 → 停止该子项，不强行上 P2；
- P2 迁移无法保证旧复习记录/旧产物 → 停止迁移，保留旧读取；
- S13B 无法证明旧复习记录/来源覆盖完整 → 停止分段，不启用；
- 任何付费测试超预算或输出不可核对 → 立即停止。

## 10. 最终“完成”的定义

同时满足以下条件才算完整优化：

1. 全量测试 + 矩阵全绿；healthcheck PASS；
2. 同一输入、同一设置下，核心产物/API 字段/页图/复习记录与旧版兼容；
3. 冷/热/失败/恢复/并发/超时六类基准均有数据；
4. 无真实数据被基准/测试写入；无密钥进入日志/缓存；
5. 旧缓存/旧产物不会被自动付费重跑；
6. 付费测试有记录，费用可解释；
7. 每个新路径都有独立回退开关；
8. 不宣称“整体一定更快”——只报告实际测量的阶段收益和边界。
