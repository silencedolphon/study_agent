方式一：从本机路径导入（推荐，尤其适合大文件或整个文件夹）
看板在本机运行，可以直接读磁盘——不走 HTTP，没有大小限制、不吃内存， 几百 MB 的 PDF 或几十个文件一次导入都没问题。

把文件拖到这里松手 → 上传进 raw\
放到哪个子文件夹由上面「方式一」那一栏决定（留空＝raw\ 根目录）
☐ 上传后立即入库（要花识图钱，默认关）
拖拽走的是浏览器上传（multipart），所以单个几百 MB 的文件可能被浏览器自己掐断 （实测 645MB 会 fail to fetch，服务端根本没收到）——那种文件请走上面的「方式一」。拖进来的文件 只放进 raw\，不会自动入库：入库要识图（约 25 秒/页且按页计费），勾选与提交仍由下面的 「批量入库」决定，与「方式一」逐字同义。
教材入库（专线）——教材只从这里进，别用下面的「入库全部待处理文件」
☐ 内容未变也重跑（会重建块的 id，引用它的知识点出处会失效）
一条龙，不问第二遍：文件先拷进 raw\教材\，再用本地 OCR 识图 （免费、不调视觉模型、约 2~16 秒/页），然后按章切块入库（章内仍按 700/1100 字切，只保证不跨章）。 这是长任务、串行的：几百页的教材要跑一两个小时，期间可以离开这一页。
入库后这份资料会被打上 chunk_scheme=textbook-v1 标记，「入库全部待处理文件」与批量入库遇到它会 跳过——不会用旧切块把按章切块覆盖掉。
跑完这里会列出识别到的章（章号 + 章名 + 页范围）与块数变化，供你事后核对； 章识别失败（少于 3 章）会如实标成"降级"，不假装成功。
这种方式只是把文件放进 raw\，不会自动入库—— 方便你先确认放在哪里。之后点下面的「入库」才会解析并建立索引。也可以直接用资源管理器把文件拷进 G:\study_agent\raw，然后点刷新。
8 个待入库
「入库全部待处理文件」两个库一起入：一份资料进哪个库由它所在的目录决定， 不由此按钮决定，所以两个子页签下都显示它。
删掉资料后，以它为出处的知识点会失去支撑。删文档时已自动清理这类孤儿记录； 若之前留下的历史孤儿还在，点「清理无出处的记录」一并收拾。
方式二：导入分享包（.zip）——别人用「导出」键打出来的课件包，里面已经带着切块、向量与 知识点总结：导入后立刻能检索、能问答，不调用任何模型、不花一分钱接口费。
导入前会先核对整包（逐条 sha256）与向量模型：模型与本库不一致就拒绝导入 并告诉你该怎么办，绝不用"重算一遍"偷偷花掉接口费。
批量入库 勾多份 → 多管线并发跑
勾选本库的待入库文件，指定并发数，一次提交多份**同时**跑入库管线； 并发只决定"几份一起跑"，不改每份的处理过程（提取文字 → 识别图片 → 分析结构 → 切块嵌入 → 写入库）。
某一份失败不影响其他份，失败原因逐条列出并可单独重试；识图要花钱（实测约 25 秒/页）， 点开始前会先给出待处理数与预估开销。

本原型改了什么（逐条）

现在在哪改后在哪为什么
4 个导入入口平铺（各带输入框 + 成段说明，共 13 段文字） 一行 4 个入口按钮 → 点谁开谁的弹窗，说明随入口进弹窗 四者语义完全并列，没有主路径——正因为并列才不该全摊开。选哪个才看哪个的说明
「入库全部待处理文件／全部强制重建／清理无出处的记录／刷新列表」四个平级按钮 只留「入库全部待处理文件」当唯一主 CTA，其余进「⋯ 更多」 四个权重相同 → 每次都要重新判断该点哪个。实际只有第一个是日常动作
批量入库整张卡片常驻（含 5 个按钮 + 158 字说明） 收进「批量入库」弹窗，入口带待入库数角标 典型"偶尔做一次、一次操作很多"。常驻时与两张表抢注意力——现状这一页同时有 3 张表
列表上方常驻「全选／全不选／批量删除选中…」 勾选任意行后才浮出操作条 一个都没选时这三个按钮毫无意义。功能不减、噪声归零
每行 5 个按钮（重建／导出／改标题／改名／移除） 留 1 个主按钮 + 1 个「⋯」，5 个功能一个不少 34 行 × 5 = 170 个按钮，是资料页 364 个按钮的最大来源
孤儿记录整张卡片常驻 折叠成一行提示条，点击展开 异常态，平时 0 个；出现时要显眼，但不必平时占版面
二级页签「教材与课件 8 待入库」原地保留 它是导航不是操作。收纳导航 = 让人迷路
顶部 8 标签 + 学科切换 + ⚙设置全部保留 同上。设置中心本身就是收纳容器，是收纳的终点，藏起来等于找不到填密钥的地方

⚠ 必须保留的安全告知（收纳但不弄丢）

告知改后位置为什么不能删
识图要花钱（约 25 秒/页，按页计费） 拖拽/上传弹窗 + 批量入库弹窗 + 上传后立即入库复选框旁 唯一会花钱的动作，必须在触发前看见
删除不可逆（真删库记录/切块/向量/知识点出处 + 四处产物） 批量删除确认弹窗内（点执行之前） 不可逆操作必须二次确认；现状有确认但说明放错了地方
