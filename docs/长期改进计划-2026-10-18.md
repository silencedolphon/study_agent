## 0. 先决决策：一次开发，三种场景（不是三个版本）

### 0.1 结论

**做一套产品 + 三个"场景预设"，不做三个独立版本。**

理由（按对单人/AI 协同开发的权重排序）：

| 维度 | 一套产品 + 三场景 | 三个独立版本 |
|---|---|---|
| 共享代码量 | **约 75–80%** 完全共用（资料/检索/出处/AI 问答/知识点/复习/笔记/设置/数据层） | 每版都要重复这 75–80% |
| 长期维护成本 | 修一次 bug，三场景同时受益 | 修 3 次；三个 schema/三套测试/三次回归 |
| 验收成本 | 一套 67 条回归 + 三角色复测 | 三套回归 + 九次角色复测 |
| 发布成本 | 一个包，或 release_pack 用预设生成 3 个包 | 三条构建/发布流水线 |
| 数据与迁移 | 用户数据（资料、笔记、知识点）三场景共用，切换不丢 | 换版本要迁移/复制数据，易分叉 |
| 风险 | 场景差异用 feature flag 控制，可控 | 代码漂移、修复回灌困难（这正是本项目灾后恢复踩过的坑） |
| 适用前提 | 单人/小团队、个人本地工具 | 有多人团队 + 明确的外部客户分层 |

**唯一的例外**：如果以后要分发给不同人群，仍然**不要 fork 代码**；用同一仓库 + 构建预设（`release_pack.py` 生成"学习版/冲刺版"等安装包，仅改默认配置与首页），保持单一源码主线。

### 0.2 三类学生需求怎么映射到"一个产品的三个场景"

| 场景预设 | 面向 | 首页默认 | 导航/信息 | 差异化组件（真正要单独做的） |
|---|---|---|---|---|
| **A 日常学习**（默认） | 学霸 + 所有人 | 今日任务 | 全导航 | 进阶能力：键盘流、导出 CSV/Anki、图谱、批量操作（属于"高级设置"，不绑死场景） |
| **B 备考目标** | 保研边缘 | 目标进度 + 今日任务 | 全导航 | 目标卡（考试日/保研线/单科目标）、倒计时、进步趋势、周计划、短板识别 |
| **C 考前冲刺** | 突击生 | 冲刺仪表盘 | 精简导航（冲刺/问答/资料） | 必背清单（3 档优先级）、剩余量/倒计时、手机优先布局、隐藏进阶入口 |

- 场景差异 = **默认落地页 + 导航顺序/可见性 + 信息密度 + 若干专属卡片**；共用同一套数据与后端。
- 学霸的"效率需求"（快捷键/导出/图谱）做成**跨场景的进阶能力**（默认开启、可在设置里关），不单独开第四个模式。
- 实现：设置中心加 `学习场景`（A/B/C，默认 A），存 `config.local.json`；前端只做三处分支（首屏、导航、密度），专属卡片按场景挂载。**任何新功能先问一句"这是场景专属，还是所有人受益"**——后者进底座。

## 5. 每阶段验收（Definition of Done）

**M0**：新用户从打开到「第一个知识点进复习队列」≤60 秒；错题可记可查；掌握度四处一致；空态无死链；390 宽无横向滚动；检索回归 ≥8/10；`tests/run_all` 全绿。

| 风险/依赖 | 影响 | 应对 |
|---|---|---|
| 单人 + AI 协同，时间有限 | 计划延期 | 每阶段可独立停；M0 优先；用子智能体承担对比评测/回归/文档，Lead 只做决策与验收 |

| 需求膨胀 | 范围失控 | 本表外的新需求先进"待评估池"，每两周评审一次；P0 未清前不加新功能 |

## 7. 变更管理与复测机制

1. 每周一：从本表挑本周任务 → 建 Team 任务卡（写清验收 + 写作用域）→ 并行分派。
2. 每个任务：改代码 → `tests/run_all.py` + 关键路径截图/API 证据 → Lead 验收 → git commit。
3. 每阶段末：**用同一套角色旅程**（`_work/eval/README.md` 的 J1–J9）让三个角色智能体复测，记录"改前/改后"分数、步数、耗时。
4. 每次复测后：更新本表状态列、更新 `docs/三类学生评测报告` 的分数、把新发现的问题放进"待评估池"。
5. 发布前：`healthcheck` + 全量回归 + 发布包审计 + 备份，四项缺一不可。
