## 3. 阶段二：P0 运行时隔离与费用安全

### 3.1 RunContext（P0-A）

新增 `core/pipeline_runtime/context.py`：

- `RunContext`（frozen dataclass）：

```text
run_id / pipeline / subject_id / db_path / log_dir
model / api_base / thinking / reasoning_effort
max_tokens（0 = 不发送 max_tokens）
prompt_version / schema_version / credential_ref / doc_id
```

- `make_context(pipeline, subject=None, doc_id=0)`：任务入口**只读一次**实际设置；
- 密钥只存 `credential_ref`（管线名），**不存密钥正文**；
- `PIPELINE_RUNTIME=0`：回退旧全局路径，并明确 `isolation=False`，不把回退模式算成隔离。

`core/chat.py` 的 `chat_once/stream_chat` 增加可选 `run_context=None`：

- 默认不传：**逐字旧行为**；
- 传 context：model / api_base / thinking / reasoning_effort / max_tokens 全用快照；
- 不再读当前管线 `config.token_cap()`；
- `max_tokens=0` 不发送字段；
- 凭据按 `credential_ref → config.pipeline_key → 旧凭据链` 解析；
- 流式/非流式/AgentRequest 均覆盖。

验证：`test_37` 8/8、`test_38` 9/9。

### 3.2 remote_unknown（P0-B）

新增 `core/pipeline_runtime/state.py`：

- 状态：`planned/running/done/failed/partial/cancelled/remote_unknown`；
- `RemoteUnknownError(remote_unknown=True)`；
- `request_may_have_been_sent()` 保守判定：

| 异常 | 是否可能已发送 | 处理 |
|---|---|---|
| `HTTPError`（含 429/5xx） | 否（有服务端响应） | 已知失败；429/5xx 可按旧策略重试 |
| `URLError` / `RemoteDisconnected` / `socket.timeout` / 连接中断 | 是 | unknown，**只允许一次请求** |
| `KeyError/TypeError/ValueError/无密钥 ChatError` | 否 | 发送前/已知失败，普通处理 |
| 适配器异常 | 不分类 | 原样上抛，不自动重试 |

上层重试循环遵守：

- `kp_build._v2_call/_gen_one`：unknown 不重试；
- `preview._preview_call`：unknown 不重试；
- `figures._http_post`：网络异常立即返回，不再 `range(retries)`；HTTP 429/5xx 保留重试；
- `textbook_kp`：attempts/telemetry/进度记录 `remote_unknown`。

验证：`test_39` 22/22。

## 4. 阶段三：P1 本地复用与缓存

### 4.1 data_revision（WAL 安全）

`core/db.py`：

- `data_revision(conn)`：读 `meta.data_revision`，缺失=0；
- `bump_data_revision(conn)`：单条 UPSERT 原子 +1，**不自行 commit**；
- `core/ingest.py::_write_chunks` 在 chunks/embeddings 成功、同一事务 commit 前 bump；
- 不使用 DB 主文件 mtime/size 或 `PRAGMA data_version` 作为全局缓存键。

### 4.2 章节/材料缓存

`core/preview.py`：

- `list_chapters` 缓存键 = `db_path + doc_id + data_revision + sections 产物内容 sha256`；
- `read_chapter_ch` 材料缓存键 = `db_path + doc_id + chapter + data_revision + 本章 block_ids + 每块 content_hash`；
- 命中 deepcopy；revision=0/无块不缓存；
- `PREVIEW_CHAPTER_FAST` 语义不变，fast/slow 输出一致。

`core/embed.py`：

- `embed_documents_cached()` 进程内 LRU(4096)；
- 键 = 实际文本 sha256 + 模型 repo/ONNX/维度/max_tokens/pooling/归一化指纹；
- 只存向量，不存正文；不同模型/维度不混用；
- 旧 `embeddings` 表/旧向量读取不变。

### 4.3 入库一次解析 + 页图/视觉缓存

`core/figures.py`：

- `extract_pages(..., pre_extracted=None)`：有预提取页数据时不再调 `extract_pdf/pptx`；
- `ingest_document_figures(..., pre_extracted=)` 透传，`stats["extract_reused"]`；
- `ingest.py::_page_pre_from_res` 用**OCR 追加后的实际入库 res.blocks**生成页数据，视觉上下文不丢 OCR；
- 开关 `INGEST_REUSE_EXTRACT=0` 回退旧双解析。

`render_pages(pages=...)` 语义修正：

- `None` = 全部；`[]` = 不导出；指定集合只渲染这些页；缺页不产出；
- `tools/render_pptx_slides.ps1` 增加 `-Pages`，只导出选中页；
- `render_pages_cached()` + `outdir/.render_cache.json`：源文件 sha256 + 后端版本 + kind + width + dpi + 页清单；
- 完整命中 0 渲染/不启动 PowerPoint；文件/参数变化/缺页才补渲染；
- 无 manifest 旧目录按旧行为渲染，不删旧页图；`FIGURE_CACHE_V2=0` 回退。

视觉缓存：

- `visual_cache_key` 包含页图 hash + 实际页上下文（含 OCR）+ 提示词版本 + 模型/端点 + 推理/输出设置 + 输出格式；
- sidecar `slide_XX.visual.json` 只存 key；
- 旧缓存无 sidecar = legacy，继续按旧规则复用，**不自动重跑付费**；key 不匹配才下次显式重新识图。

测试：`test_40` 9/9、`test_41` 12/12。

### 8.3 关键行为证据

- `PIPELINE_RUNTIME=0`：所有管线回退旧全局路径，测试明确断言“不声称隔离”；
- `PIPELINE_RUNTIME=1`：两个线程/两个任务使用不同 context，model/max/thinking/effort 不串；
- 运行中切换设置不影响已建 context；
- `remote_unknown`：fake urlopen 抛 `RemoteDisconnected/URLError/timeout`，上层只请求 1 次；
- `HTTP 503`：仍按旧策略重试（已知失败）；
- single-flight：8 线程同键只一个 winner，A/B/release/stale/force 全部覆盖；
- WAL 测试：主 DB `st_mtime_ns` 不变但 `data_revision` 变化，缓存正确失效；
- 视觉缓存旧目录/旧缓存无 sidecar：legacy 复用，不自动重跑；
- v2 分段：只在 force 生成，v1 signature/点 ID 不变；
- 复习迁移：唯一最佳才迁移，歧义/无匹配清单，旧 review 备份可读。

## 11. 仍需明确记录的边界 / 风险

以下内容**没有**在本轮完整实现，GPT 审阅时应重点看：

1. **S16 不是完整拆分**  
   只拆了四组低风险纯函数/只读读取；`build_v2/gen_kp_v2/plan_kp_tasks_v2` 仍在 `kp_build.py`。没有为了“拆而拆”搬动并发/认领/落盘主流程。

2. **S14 只是实验**  
   `plan_small_node_merge()` 只读模拟，默认关、未接真实 build；没有真实质量样本证明“合并小节点”能提高总结质量。

3. **KP 节点级模型结果缓存未单独实现**  
   页面归属做了回归加固；模型结果续跑主要依赖既有 artifact/parts + stage cache（textbook plan）。如果 GPT 期望的是“按 KP 节点缓存模型输出”，这仍是后续项。

4. **single-flight 只在 textbook_kp 接入**  
   其余管线仍靠 active 状态/开关；跨进程同对象并发保护没有全部铺开。

5. **没有真实付费 A/B**  
   全量测试零真实模型；本地微基准只测准备路径。真实模型耗时/费用是否下降、缓存真实命中率多少，需要小样本付费实测。

6. **真实主库 `data_revision=0`**  
   优化测试没有写真实库，因此当前部分缓存自动走旧路径；下次真实入库 bump 后才生效。需要确认所有 chunk 写入路径都 bump（目前重点在 `ingest._write_chunks`）。

7. **分段 v2 未在真实章节启用**  
   默认关闭；开启需 `TEXTBOOK_KP_SEGMENT_V2=1` + `force`，并观察复习迁移的 `migrated/unmatched/ambiguous` 清单。没有真实章节质量对照。

8. **UI 未新增展示**  
   `remote_unknown`、partial、settings_changed、coverage 等主要在后端字段/产物/报告；前端没有新增可视化。用户如果希望在界面直接看到这些状态，需要单独的 UI 卡。

9. **缓存/telemetry 运维**  
   `stage_cache.sqlite`、telemetry JSONL、锁文件目前没有自动清理策略接入看板；需要后续决定保留周期/大小上限。

10. **S08B 名词缓存收益较小**  
    实测 0.580→0.290ms，收益有限；可长期 `SHARED_MATERIAL_CACHE=0`。

## 12. 建议 GPT 重点审阅的问题

1. `RunContext` 对 **max_tokens=0** 的统一语义是否正确？  
   当前 chat/outline 端点为了保持旧默认，把“设置 cap=0”替换成端点缺省（2048/32768）；这会不会与“0=无上限”的全局约定冲突？是否应该改由设置中心显式给缺省值？

2. `remote_unknown` 保守判定是否过宽？  
   当前 `URLError` 一律视为“可能已发送”，宁可少重试；是否需要区分 connect 阶段失败（可安全重试）与 read 阶段失败？

3. `data_revision` 的写入覆盖面  
   目前只在 `ingest._write_chunks` bump；如果未来有别的写 chunks 路径，缓存会失效不完整。是否需要统一写入口/触发器？

4. `stage_cache` 的 key/版本/清理  
   当前 key 含 config/input fingerprint，旧 cache miss 保留；长期运行是否需要 TTL/大小上限/手动清空入口？

5. `S16` 的边界是否可接受  
   只拆纯函数和只读读取；是否要继续拆 `build_v2/gen_kp_v2/plan_kp_tasks_v2`，还是保持现在的“低风险模块化”？

6. `S14` 节点粒度实验  
   当前只读模拟；是否值得用真实产物做一次“合并前后”质量对照，再决定是否接入？

7. `S13B` 分段 v2  
   节标题/段落/16k 的优先级是否符合教材真实结构？复习迁移的 source Jaccard + 标题阈值是否合理？需要真实样本评估。

8. UI 是否需要暴露  
   哪些后端字段应该让学生看见（unknown/partial/coverage/settings_changed），哪些只留在日志/报告？
