# 性能优化实验：章级材料快速路径（2026-10-31）

> 输入：GPT 的《学习管线架构与性能优化框架》（2026-10-30）。
> 本文记录**可行性判断、实际改动的一版、测量方法与结果、未做部分**。
> 结论先说：**局部章级材料路径有明确优化（约 1.6–1.9×，且读取量减少约 97%），
> 但不能据此宣称整个看板/模型生成快了；本次没有真实模型调用，也没有改模型输出。**

---

## 1. 对 GPT 方案的可行性判断

GPT 的方案本身是合理的，但它是**架构级路线**，不能一次性全做。按风险/收益拆分：

| GPT 建议 | 本次判断 | 原因 |
|---|---|---|
| P1：章级材料定向读取（只读本章 block，不再整本读） | **采纳并实现** | 零模型、输出可逐字对比、可测量；收益确定 |
| P1：复用章节目录中的 block_ids，避免二次整表扫描 | **采纳并实现** | 同一份 `list_chapters` 已经聚合过 block_ids，`locate_chapter` 又扫一遍纯属重复 |
| P1：全页图缓存/选择性渲染、入库一次解析复用 | **未实现** | 涉及 PowerPoint COM/旧缓存/`/img/slide` 展示页完整性，需真实 PPT 样本与更多回归；本轮不做 |
| P1：向量复用（按真实输入+模型版本） | **未实现** | 需要嵌入模型/归一化一致性测试；当前入库路径不是瓶颈 |
| P0：RunContext 配置/学科隔离、远端 unknown 状态 | **未实现** | 属于可靠性改造，应单独开一轮并加并发/超时测试；本轮先做可测的读侧优化 |
| P2：阶段缓存/断点/旧格式迁移 | **未实现** | 迁移影响面大，尤其旧教材产物/复习记录；本轮只做不改产物的快速路径 |
| P3：分段提示词/节点粒度/质量改造 | **未做** | 会改变模型输出和费用，必须用户授权、离线样本对照；本轮零 AI |
| P4：Agent 扩展 | **不做** | 已有 opt-in 边界；本轮不启用外部 Agent |

本轮的取舍：**先做 P1 中“纯本地、可回滚、输出等价”的一小块**，用同一材料/同一设置测量，
不触碰模型输出、数据库内容、历史产物和用户笔记。

## 2. 实际改动

### 2.1 `core/kp_build.py`

新增：

```python
read_text_pages_by_ids(doc_id, chunk_ids, db_path=None)
```

- 与 `read_text_pages()` 相同的 `blocks/cover/figrows/pages_all/n_blocks` 结构；
- 只 SELECT 指定 chunk 集合，块解析、跨页覆盖、图片理解标记完全复用；
- 任何给定块の `source_ref` 解析失败仍然报错，不静默丢块；
- 章级块数通常几十个，按 500 个一组分片查询，避免 SQLite 变量上限。

### 2.2 `core/preview.py`

- `list_chapters()` 的章节对象新增 `block_ids`（后端内部/兼容字段，前端忽略即可）；
- `locate_chapter()` 命中 `heading_path` 时直接复用 `hit["block_ids"]`，
  **不再调用 `agg_block_ids()` 做第二次整表扫描**；旧数据无该字段时自动兜底；
- `read_chapter_ch()` 默认走快速路径：
  1. `locate_chapter()` 先定位本章；
  2. `read_text_pages_by_ids()` 只读本章块；
  3. 与旧路径共用 `_assemble_chapter()`，保证 ch/material/inv/stats 口径一致；
- 旧整本路径保留为 `_read_chapter_ch_slow()`，环境变量 `PREVIEW_CHAPTER_FAST=0` 可回退。

### 2.3 `core/textbook_kp.py`

- `_plan()` 默认先按 `heading_path LIKE '%第N章%'` 定向查询；
- 若筛选为空（旧数据/章号格式不同）自动退回整表扫描；
- `TEXTBOOK_KP_FAST_PLAN=0` 回退旧的整表路径，供 A/B 对照与回滚；
- 产物签名/分段/复习记录不变（测试锁定 fast/slow 的 signature 完全一致）。

### 2.4 基准工具

新增 `tools/bench_pipeline.py`：只读同一 DB、同一章节，分别以
`PREVIEW_CHAPTER_FAST=0/1`、`TEXTBOOK_KP_FAST_PLAN=0/1` 跑旧/新路径；
不写真实库、不调模型。

## 3. 基准与结果

### 3.1 环境与方法

- 机器：本机 Windows，Python 3.13.2，项目 venv；
- 数据：`D:\study_agent\index\study.db`，教材 doc#50《药理学 第6版》，章节 1/6/20/39；
- 只读（SQLite `mode=ro`），零模型调用；
- 单次测量取 N 次 median；先预热；同一进程依次跑旧/新；
- **注意**：本机同时有浏览器/聊天/后台进程，墙钟时间会波动；所以同时记录
  “实际读取块数/字符数”这种确定性工作量作为主证据，墙钟值只作为方向性参考。

### 3.2 确定性工作量（doc#50 第6章）

| 指标 | 旧路径 | 快速路径 |
|---|---:|---:|
| 读入的块数 | **882 块**（整本） | **24 块**（本章） |
| 读入的正文字符 | **633,533** | **17,545** |
| `locate_chapter` 全表扫描 | 2 次（list + agg） | 1 次（list 复用 block_ids） |
| 章级材料/产物 | 相同 | 相同（逐字 hash 相等） |

即：**章级读入量减少约 97%**，第二次 882 块扫描被消除。这是本次优化最确定的部分。

### 3.3 墙钟时间（安静窗口，N=10，第6章）

| 调用 | 旧路径 median | 快速路径 median | 约 |
|---|---:|---:|---:|
| `preview.read_chapter_ch` | 30.8 ms | 16.3 ms | **1.9×** |
| `preview.estimate_preview` | 36.4 ms | 22.9 ms | **1.6×** |
| `textbook_kp._plan` | 13.3 ms | 7.7 ms | **1.7×** |

说明：本次机器上其他进程会让数字上下浮动（同一脚本另一次跑出过相反方向），
所以上表只用于说明**调用路径变短**；不能当作稳定的 P95 或全站加速承诺。

### 3.4 输出等价

对 doc#50 第 1/6/20/39 章，比较 `ch`、`info`、`material`、`inv`、`stats` 的 SHA256：

- 快速路径 vs 旧路径：**0 处不一致**；
- `textbook_kp._plan` fast/slow：**签名、分段数、字符数一致**；
- 新测试 `tests/test_36_opt_chapter_fastpath.py` 4/4 通过。

### 3.5 回归

- 功能矩阵：**92 行，覆盖 92/92**（新增 F128）；

## 4. “整体优化了吗？”的判断

**分项回答：**

- **章级材料准备（本地 CPU/DB）**：是，明确变快，读入量减少约 97%；
- **预览/教材知识点的本地准备阶段**：是，约 1.6–1.9×；
- **真实模型生成耗时/费用**：**没有变化**——本次没改提示词、模型、输出 schema、调用次数；
- **整个页面/看板的总耗时**：没有证据说整体变快。页面加载和生成仍主要受
  模型调用、浏览器渲染、图片渲染等影响；本次只缩短了“送模型之前的本地准备”；
- **稳定性/正确性**：没有回退；fast/slow 输出等价，且保留环境变量回退。

所以报告结论是：**“这次优化对章级本地材料路径有效，但不能宣称项目整体性能已全面优化。”**
若要验证“整体”，下一步应该按 GPT 方案做 P0/P1 的任务级基准（页面/API/模型/缓存分开计时），
而不是只看一个本地函数。

## 5. 回退与开关


默认均为 1（快速路径）。两开关只影响本地读路径，不改变产物格式/模型调用。
旧路径代码保留（`_read_chapter_ch_slow`），没有删除任何功能。
