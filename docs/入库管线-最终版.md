## 管线做了什么

对每份资料依次五步，全部由 `core/ingest.py::ingest_file` 编排：

```
0. 【PDF 专有】检测是不是"一页拼了多张幻灯片"（见下一节）
   └─ 是 → 先切成"一页一张"，后面所有步骤拿到的都是正常 PDF
1. 提取文字
   ├─ pdf  ：版面感知（按 text block 分组 + 字号判标题），硬折行归一化
   │         └─ 扫描/截图页 → OCR
   │              └─ **表格按二维还原**（检测表格线 → 网格 → 每行自带行名与列名）
   │                   └─ 另出一个**整表概览块**（跨行聚合提问用）
   └─ pptx ：形状**按坐标重排**（图上标签不再竖着堆），表格按行号对齐
2. 整页识图（图片理解）
   ├─ 渲染整页 PNG（pptx 走 PowerPoint COM，pdf 走 pymupdf）
   ├─ pptx 按形状过滤"没有图片对象"的页（免费，实测省约六成调用）
   ├─ 有描述且图片哈希未变 → **复用，不重复计费**
   ├─ 逐页调视觉模型（整章语境 + 推理模式）
   └─ 按【】小节切块入库，标记为「图示说明」/ `p.N 图`
3. **AI 全局结构分析**（画思维导图 → 给每页定路径）★ 详见下一节
4. 切块
   ├─ 语义边界（标题/段落/幻灯片）+ 面包屑（取自第 3 步的路径）+ 出处区间
   ├─ 零丢弃契约：短块四轮合并，任何内容都不许被静默丢掉
   └─ `group` 分组边界（表格每行一块，避免整表挤成一块）
5. 嵌入（本地 ONNX bge-small-zh-v1.5 int8，512 维，不联网、不花钱）→ 写库
   └─ 识图块按导图路径重建一次，与正文块挂在同一个节点下
```

**顺序有讲究**：识图排在切块**与全局分析之前**——识图描述里有
"这页是三种药的对比表"这类正文没有的结构线索，模型判层级要用它。
见下一节。

## 第 0 步：一页拼了多张幻灯片的 PDF（**入库时自动处理**）

用户实测反馈：

> 文件名开头带"卢"的 pdf 有点奇怪，它是好多张 PPT 放在一页组合成的，
> 这对识别和切块不是很友好……我的想法是在得到一份 pdf 时**先检测**是否
> 一页集成了多张 PPT 图片，如果没有就走原本的管线；如果有就需要专门有一个
> 程序把集成在上面的多张 PPT 切割下来，专门编好页码，然后再走原本的管线。

实测 `1-卢-抗高血压药 2025.pdf`：A4 纵向一页排 **2 列 × 3 行共 6 张 PPT**，
12 页装完一个章节；而正常导出的课件是 720x540 一页一张。

**不切开会怎样**：文字按 y 坐标串成一段（标题层级全丢）、一块里混着 6 张
幻灯片的内容、出处只能标到 `p.1` 指不回具体哪张、识图把 6 张缩略图一起
喂给模型（字小图糊，用户原话是"得眯着眼睛仔细看"）。

### 检测：几何分割，不靠图片对象

一页里确实有多个图片对象，但它们是**幻灯片内部的小图**
（实测第 1 页 6 个图对象，尺寸 57x75、39x89、142x142……散落在各张幻灯片
内部），**不是"一张幻灯片一个图"**——按图片分组会切得乱七八糟。

改用**几何分割**：幻灯片在页面上是网格排列的，格子之间是干净的空白带。
把页面渲染成位图，逐行/逐列数非白像素，全白的行/列就是格子边界
（页眉、页码落在格子之外，不会破坏空白带）。

**抽样检测**：只看前 3 页。这种资料每页都长一个样，不必为了判定把几百页
全渲染一遍——实测一份 13 页的检测只要 **0.3 秒**。

### 切分：矢量搬运，不是截屏

用 `show_pdf_page` 把源页的某个矩形**贴**到新页上，**不会二次损失清晰度**。
新 PDF 页码 = 幻灯片序号（1..N），按从左到右、从上到下排；同时写一份
`*.pages.tsv` 映射表（新页号 → 原第几页的第几格），要回溯原始文件时用得上。

### 自动化的边界

`ingest_file` 在**提取之前**检测（`.env` 的 `SPLIT_MULTISLIDE=1`，默认开）：

- 是这种资料 → 自动切到 `<名字>_slides.pdf`，**用切割版入库**；
  原文件**不在库里留记录**，所以下次全量重导入会重新检测、再次指向切割版，
  不会重复索引；
- 不是 → 原样走；
- **检测/切分出任何问题都按普通 PDF 处理**，绝不让它挡住入库。

命令行入口 `tools\split_multippt.py` 保留三个用途：先看看哪些是这种资料
（`--scan`）、补切已有资料（`--src`）、切歪了排查（`--detail`）。



**这一步已在主流程里，不需要额外调用任何脚本。**

```
提取文字 → 整页识图 → 【大模型看完整份课件、画思维导图、给每页定路径】→ 切块 → 嵌入 → 写库
```

### 解决什么

用户实测反馈：

> P26 的标题是「巴比妥类的药理作用与临床应用」，P27 是「巴比妥类的镇静催眠作用」。
> 我问 AI「巴比妥类的药理作用」时，检索不到 P27 的内容。
> 根本原因是 P26 和 P27 之间的**结构信息丢失了**。

p.27 是 p.26 **底下的一项**。逐页局部推断只会给每页各起一个名字、
把它们变成并列的兄弟，这层从属关系就没了。所以让模型输出**路径**：

```
