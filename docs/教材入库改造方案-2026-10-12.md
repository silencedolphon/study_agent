## 一、人的原话

> 「入库管线修改一下：**把课件入库和教材入库分开**。在**资料栏专门开一个按钮**来负责教材入库。教材入库时，**先用 OCR 识图把文字识别出来**，然后再**按照每一章分别切块**，**不要像之前一样所有东西都挤在一起**。考虑一下如何改造原有管线以适应要求」

## 二、现状（每条都有锚点）

### 2.1 教材与课件在管线里**没有任何角色分流**

- 入口 `core\ingest.py:974 ingest_paths` → `:262 ingest_file`。
- 教材(PDF) 与课件(PPT) 的**全部**差别只有 4 处，且都是扩展名的副作用：
  - `extract.py:1040-1045` 提取器分派
  - `ingest.py:354-374` PDF 专有「一页多张幻灯片切分」
  - `ingest.py:407-417` PDF 专有「扫描页本地 OCR」
  - `extract.py:829` → `chunk.py:44 / 527-528` pptx 专有 `SLIDE_MIN_CHARS=8`（PDF 用 80）
- `documents.role` 列**存在但只在写库时算一次**（`ingest.py:936/943`、`db.py:540-553`），仅供问答检索分组
  （`chat.py:383-388`）与徽章（`dashboard.py:7399`）；**检索层 `search.py` 不用 role，只用 corpus**。
- `classify_role()` 的判据是 `f"{title} {path}"`（`db.py:547`）⇒ **放进 `raw\教材\` 的文件会自动判成 `textbook`**（可直接复用）。

### 2.2 「按章切块」完全不存在

- 切块策略：语义边界 + **700 字目标 / 1100 上限 / 120 重叠**（`config.py:121-124`），边界来自标题块、页变化、长度、表格 group ⇒ **没有「章」这一级**。
- 实测教材 doc#91《药理学 第6版 刘晓东》：**867 块 / 624,239 字符**，`heading_path` **只有 1 种**（=书名），
  `topic` 全 NULL，块长 380~794（均值 720）。
- **铁证**（ord=400，`source_ref=p.218`）：`…5.抗高血压药合理用药的原则有哪些？…本章小结 **第二十章 治疗心力衰竭的药**`
  ⇒ **第十九章结尾与第二十章标题被切在同一块里**。
- 附带污染：ord=0~5 是版权页/编委/前言；ord=6~13 整段是目录文字。

### 2.3 OCR：有两条完全不同的通道

| | (a) 本地免费 OCR | (b) 视觉大模型识图 |
|---|---|---|
| 实现 | `extract.py:441 ocr_pdf_pages` + `rapidocr-onnxruntime`(573-578) | `figures.py:1954 describe_page` |
| 成本 | **免费** | **¥0.0105/页** |
| 速度 | 16 秒/页（100dpi，`config.py:127-132`） | 25 秒/页 |
| 触发条件 | 仅「几乎无文字层」的页；开关 `with_ocr`（**后端支持、UI 无入口**） | 「提取到 0 块」才触发（`ingest.py:419/447`） |
| 输出质量 | 纯文本 | 懂版式（含图片描述） |

- **C-0066 的「图片型课件通道」是 (b) 视觉大模型**（`ingest.py:434-475` → `:680 _zero_text_vision_pass` →
  `figures.py:961 ingest_pages_as_blocks`），**不是本地 OCR**。
- ⇒ 教材要「先 OCR 识图」，**必须新建/扩展**（已有文字层的教材永远走不到 (b)）。
- ⚠ **陷阱**：`FIGURE_MAX_CALLS_PER_DOC`（默认 200）**当前无人传参**（`ingest.py:531` 未传 `max_calls`）
  ⇒ 452 页教材会真的发 452 次调用。

### 2.4 章节来源：PDF 书签不可靠，「书眉 + 章号单调」最可行

- 全项目**无 `get_toc`**；实测 doc#91 的 `get_toc()` = **0 条** ⇒ 书签不可依赖。
- `extract.py:383 cn_re` 的章标题识别只作用于**有文字层的 PDF 正文**；**OCR 块一律 `kind="ocr"/"table"`、
  永不判 heading**（`ingest.py:522-537`）⇒ 这就是扫描教材没有面包屑的根因。
- `outline.analyze_deck` 的闸门 `_should_analyze` 限 **120 页以内**（`ingest.py:760-772`）⇒ 教材永远够不着。
- ✅ **最可行**：OCR 文本里的**章标题/书眉 + 章号单调规则**。实测 doc#91：整行「第X章 xxx」命中 **332 次**、
  章号**全书单调递增**、书眉在正文页反复出现（p.435 / p.437 都有「第四十一章…」）⇒ **可零模型调用给每页定章**。
  - ⚠ **必须排除目录页（p.7-11）与编者分工页**（p.7 一页就有 28 处章号）。
- 次选：一文件一章（文件名即章名）／复用 `kp_build.py:2633 gen_structure_v2` 的 AI 分段归并（**花钱**）。

## 四、大管家已定的技术选择（技术细节，不占用人的决策）

1. **章内仍按 700/1100 切、只保证不跨章**（整章一个块对检索不友好）。
2. **已有教材重跑**（只 1 份、代价为零）。
3. **教材落盘目录新建 `raw\教材\`**（让 `classify_role` 凭路径自动判 textbook）。
4. **章标题先用正则书眉 + 章号单调**（零成本、已实测可行）；识别失败的文档**如实降级为「整份书名一级」**
   并在回执里报告，不假装成功。
5. 教材入库**必须走独立 UI 入口**，不复用批量入库的默认语义。

## 四·补、⚠ 本改造最容易踩的四个坑（子代理逐条点名）

1. **「入库全部待处理文件」会用旧逻辑覆盖教材的新切块**（最危险）
   `dashboard.py:7538` 的主按钮会把 `raw\` 下**两个子库一起入**（`:7547-7548`）。
   ⇒ 用户在「教材入库」按钮上刚做好的"按章切块"，会被**下一次通用全量入库**用旧切块抹掉。
   ⇒ **对策**：教材专线入库后给文档打标记（`documents.extra.chunk_scheme = "textbook-v1"`），
   通用入口遇到该标记时**拒绝/跳过**；按钮文案也要提示"教材请走教材专线"。
2. **重跑教材会重建 `chunk_id`**（`ingest.py:898` 先 `DELETE FROM chunks WHERE doc_id=?` 再重插）
   ⇒ `kp_sources.chunk_id` 被 **ON DELETE CASCADE** 清空（`db.py:120-125`）、`mistakes.chunk_id` 置 NULL。
   默认库当前知识点 = 0、错题 = 0，**代价为零**；但**其他学科若已有知识点产物引用了 chunk_id，重跑会使其失效**
   —— 这条必须写进卡面红线。
3. **`FIGURE_MAX_CALLS_PER_DOC`（默认 200）是死设置**（全项目无人传参）
   ⇒ 若叠视觉识图，452 页教材会**真的发 452 次调用**；教材专线里必须**显式传 `max_calls`**。
4. **教材入库是长任务**（本地 OCR 452 页 ≈ 2 小时）
   ⇒ 必须**串行**、走 `_INGEST_LOCK`，**不要塞进并发批量池**（否则 6 处 `reindex()` 调用点与并发参数都会被牵动）。

**另一条已定项**：教材入口**显式声明 `role='textbook'`**（不依赖标题启发式）——
让"教材入库"这个按钮本身成为权威声明，而不是靠文件名里有没有"教材/第N版"字样去猜。
