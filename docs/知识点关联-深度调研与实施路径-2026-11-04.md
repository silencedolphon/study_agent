# 跨课件知识点关联：深度调研与实施路径

调研日期：2026-11-04。范围：在复习课件知识点时，查看它与其他课件知识点的联系。本文件是实施方案，关联功能尚未开发。

## 一、结论：建设能解释和追溯的“知识桥”

建议建立四层结构：知识点与课件来源、规范化概念和事实、关系与路径、用于复习的交互。它应回答：

1. 两个知识点有什么联系：同一概念、机制、前置、应用、对比，还是仅有相似线索？
2. 关系是否有方向、条件和中间环节？
3. 每一步来自哪份课件、哪一页、哪一段或哪张图？
4. 资料是否足以支持，哪些是图像描述、模型推断或尚待确认？

例如，学生复习乙酰胆碱水解时，不只看到另一份课件里也出现了 AChE，还能沿“水解终止信号 → 抑制酶 → ACh 较难水解并堆积”的机制桥梁跳到药物章节。

默认只在当前学科内搜索。允许本课件知识点作为桥梁的中间节点，但最终推荐显示其他课件。首屏展示少量可解释卡片，复杂路径由用户展开，不强迫看整张大图。

### 2.3 关键发现：有出处编号不代表出处充分

课件 43“胆碱能传递概述”引用 p.28 的 chunk 1709，但该块可提取的文字只有“胆碱能神经的突触传递”标题，不能仅凭此块证明总结中全部过程。

而课件 43 的 p.33、chunk 1714 明确写到 ACh 被 AChE 水解并终止作用；课件 48 的 p.4、chunk 2447 明确写到抗胆碱酯酶药抑制 AChE，使 ACh 较难水解并堆积。这两段适合支持跨课件机制联系。p.34 的部分图示说明来自机器识图，必须与可直接查看的原图、原文区分。

因此，不能只验证 chunk ID 存在，必须检查引用是否真的支持所述关系；标题、空块、机器视觉推测和来源不足都需要单独标记。

## 三、网络研究中可借鉴的方法

### 3.1 LightRAG：局部概念与高层主题并行

[LightRAG 论文](https://aclanthology.org/2025.findings-emnlp.568/)将图结构和向量结合，兼顾低层与高层检索，并讨论增量更新。

可借鉴：低层围绕 ACh、AChE、具体药物和作用对象查找；高层围绕“胆碱能信号传递”寻找跨课件主题；新课件加入后只更新受影响的点、概念、关系和缓存。

不建议一开始直接接入完整通用框架：项目已有 SQLite、课件结构、任务队列和模型接口。直接套用可能重复抽取；是否提高效果要用本项目数据验证。

### 3.2 HippoRAG 2：用图找跨文档间接关联

[HippoRAG 2，ICML 2025](https://proceedings.mlr.press/v267/gutierrez25a.html)使用个性化 PageRank，结合原文段落和模型处理事实、综合理解及联想任务。

可借鉴：从当前知识点和相关概念出发，沿有类型的可信边找邻居，再列出实际走过的证据路径。保留直接向量和关键词候选作为兜底，因为图可能尚未构建完整。

图扩散分数只是排序信号。受体、药物等高频概念容易成为无意义的中心，需要降低其权重并限制分支数。

### 3.3 教育知识图谱：先修方向和人工纠偏

[ACE 教育知识图谱研究](https://jedm.educationaldatamining.org/index.php/JEDM/article/download/737/218)先排序可能的先修关系，再交给专家判断，并利用已有结构减少审查工作。

2026 年的 [ProPRL 预印本](https://arxiv.org/abs/2608.03006)研究先修关系的方向以及相反方向同时高分的问题。方案借鉴方向敏感和冲突检查，不声称论文指标可直接用于本项目，也不建议在标注不足时直接训练完整模型。

### 3.4 图不自动保证准确

[GraphRAG-Bench](https://arxiv.org/abs/2506.05690)讨论了图方案的效果会因任务而异；[DEG-RAG 预印本](https://arxiv.org/abs/2510.14271)指出生成图中存在重复实体和错误关系。生物医学关系抽取的 [ACL 评测](https://aclanthology.org/2025.wasp-main.6/)也发现，复杂输入中大模型仍会出错。

所以必须比较直接检索和图路径，并检查来源、方向、条件和实体对齐，而不能把生成的关系图直接视为事实。

### 3.5 知识联系应服务主动记忆

医学教育中的[系统综述](https://pubmed.ncbi.nlm.nih.gov/37615780/)支持检索练习和分散练习。可在已核验的关系卡片旁提供“先说出联系，再展开答案”。该研究不能直接证明本系统一定提升个人成绩，产品效果仍需自行验证。

## 四、用户体验与关系分类

在现有知识点窗口增加“查看知识联系”，优先展示 3～5 张卡片。示例：

> **机制联系｜两份课件**  
> ACh 被 AChE 水解后作用终止。另一份课件说明，抗胆碱酯酶药抑制 AChE，使 ACh 较难被水解并堆积。  
> 原理出处：外周神经药理学概论 p.33  
> 药物出处：抗胆碱酯酶药和胆碱酶复活药 p.4  
> 查看两处原文｜打开关联知识点｜先回忆答案

系统展示教学资料中的联系，不将其包装为个人用药建议。

| 教学关系 | 方向 | 作用 |
|---|---|---|
| 同一概念的不同表述 | 通常对称 | 统一名称、缩写和定义 |
| 机制或过程关联 | 可有方向 | 解释对象、作用和结果 |
| 原理与应用 | 有方向 | 把基础知识接到药物或具体应用 |
| 比较与易混淆 | 对称或标注两侧 | 展示共同点及差异 |
| 先学与后学 | 有方向，要求更严格 | 指出可能需要补看的前置内容 |
| 同主题但依据不足 | 不确定 | 显示线索，不编造确定关系 |

事实层的“结合、激动、抑制、增加、减少、转化”等作用类型应与上表的教学关系分开。一对知识点允许同时属于多种关系，不能强行压成一个标签。

卡片提供出处与跳转。无足够依据时，显示“可能相关，依据不足”或明确显示无结果；点击查看时不静默发送付费请求。

### 5.1 四种基本对象

1. 知识点版本：所属学科、课件、原知识点 ID、内容版本、页码和出处。
2. 概念：规范名、别名、类型、来源、确认状态，例如 ACh 和 AChE。
3. 事实断言：主体、谓词、客体、方向、极性、条件以及对应原始证据。
4. 点对关系：两个知识点版本之间的教学关系，可以由一条或多条断言支持，也可能是结构关系或人工确认。

证据记录保存课件 ID、页码、chunk ID、来源块内容哈希、精确摘录或文本区间、来源类别。引自机器生成图片描述的证据须单独标识并可跳转原图。

### 5.2 概念对齐：名字相近不等于同一概念

别名候选按层处理：

- 原文明确出现“中文名（英文名/缩写）”。
- 已有名词解释中可核验的名称与出处。
- 大小写、空格、连字符、全角半角等规则归一；保留亚型、α/β、受体与配体差异。
- 由向量或模型提出的候选只进入待核对池，不默认自动合并。
- 用户确认或撤销应有版本化记录。

反例：ANG 在不同上下文可能指不同概念；血管生成素与血管紧张素名称相似却不能合并。ACh、AChE、M 受体和 N 受体也不能混同。

### 5.3 原子事实要包含方向、否定与条件

预期结构示例：

~~~json
{
  "subject_concept": "抗胆碱酯酶药",
  "predicate": "inhibits",
  "object_concept": "乙酰胆碱酯酶",
  "polarity": "affirmed",
  "condition": "",
  "evidence": [{
    "doc_id": 48,
    "page": 4,
    "chunk_id": 2447,
    "quote": "抗胆碱酯酶药能抑制AChE",
    "content_hash": "...",
    "kind": "source_text"
  }],
  "status": "candidate"
}
~~~

校验时确认引用确实出现在指定块、块属于该课件和版本。字面匹配只能证明摘录存在，还要检查句意、否定、作用方向、剂量、受体亚型、中枢/外周等条件。不同条件下的相反效应不应自动标记为矛盾。

### 5.4 区分直接、结构、推断和待核实

- 直接证据：原文明确陈述定义或作用。
- 结构联系：同一章节、父节点或顺序，只说明学习组织，不能自动升级为因果或先修。
- 跨来源推断：必须记录每个前提、推理规则、方向和证据；任一环证据不足则整体降级。
- 推测：只有相似度、标题或不充分引用时，标记待核实。
- 人工确认：记录确认人和版本，资料更新后重新判断；不覆盖旧证据。

两条边串起来不意味着可无条件推导第三条边。只允许经过事先定义并测试的有限规则推导；不得将生成的自由文本当证明链。

## 六、召回、重排与图路径

### 6.1 多路候选

1. 知识点向量：标题、总结和精简要点。对点对比较可先用 embed_documents 作为对称基线；若改为带前缀的 embed_query，需要单独 A/B。
2. 术语与别名：中文、英文、缩写、药名和受体亚型。SQLite trigram 对少于 3 个字符的词有局限，须补精确匹配或短词策略。
3. 图路径：知识点—概念—事实—知识点，或已验证的知识点边。本课件可作中间桥，最终结果默认排除本课件。
4. 章节：手动对应的教材章节可作为辅助信号，不能证明医学机制。

对候选去重后用 RRF 等方法融合，按课件分配配额，避免长课件占满结果。允许返回零条。

### 6.2 候选精排

- 本地交叉编码器：可评估 [bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3)，只对少量候选逐对排序。原模型权重文件约 2.27 GB，本机当前未安装，也没有实测速度。采用 ONNX 导出或量化版前需验证来源、版本、哈希及与原模型的质量差异。[官方说明](https://www.sbert.net/docs/cross_encoder/usage/usage.html)指出交叉编码器常用于重排 top-k 候选。
- 受控模型判断：仅在已启用的后台任务或明确确认的按需任务中，用项目现有 DeepSeek 配置判断候选的关系、方向、条件和引用。可小批处理，必须限制批数、输入输出 token 和重试。

重排器估计“值得继续看哪对”，不能自行把分数升级成事实。

### 6.3 桥梁与图扩散

首版开放直接关系与经过一个中间知识点的路径。示意：

~~~text
胆碱能传递概述（课件 43）
  └─ 同一课件的过程细节 → ACh 水解消失（课件 43，p.33）
       └─ 同一作用对象和机制 → 抑制 AChE 的药物（课件 48，p.4）
~~~

如引入个性化 PageRank，可用当前点及可信概念形成种子向量 s，并在过滤后的图上迭代：

~~~text
r_next = (1 - a) * s + a * P.T @ r
~~~

P 需要按边的类型、方向、证据状态构建并处理无出边节点；不能把先修关系反向解释为先修，也不能用同章节冒充因果。图扩散只用于产生候选和排序，展示仍需具体证据路径。高频概念按出现文档数折减权重并限制分支。步数、权重和候选量是待标注集验证的参数，不应凭直觉固定。

### 6.4 “关系程度”与“证据状态”分开

- 学习相关性：排序信号，回答现在看这条是否有帮助。
- 证据状态：直接引用、跨来源推断、资料不足、人工确认。
- 正确概率：只有在独立标注与校准集充分时才考虑输出。把分数过 sigmoid 只是数值映射，不等于校准，参考 [scikit-learn 概率校准说明](https://scikit-learn.org/stable/modules/calibration.html)。

第一版使用“直接联系 / 通过中间环节 / 待核实”，不显示未经校准的百分比。

## 七、存储、身份和增量更新

建议每学科使用旁路 SQLite，例如 logs/knowledge/relations/relations.sqlite；不改写课件 JSON 真源，也不挪用旧 kp_edges。关闭功能或旁路库不可用时，原看板应继续工作。

| 表 | 核心内容 |
|---|---|
| relation_builds | run_id、学科、输入版本、状态、模型/提示词/规则版本、token 和错误 |
| point_versions | 学科内部身份、doc_id、kp_id、内容版本、标题和原文哈希 |
| point_embeddings | 知识点版本、模型签名、维度、向量；与现有 chunk 向量分开 |
| concepts / concept_aliases | 规范名、类型、别名、来源、确认状态 |
| assertions | 主体、谓词、客体、极性、条件与抽取版本 |
| evidence | 断言/关系、课件、块、页码、精确摘录、内容哈希和来源类别 |
| relations | 两端知识点版本、教学类型、方向、状态和来源 |
| relation_paths | 起点、终点、有序边、规则/证据版本和状态 |
| feedback | 关系版本、是否有帮助/不准确、原因和时间 |

每条边绑定两端具体版本。对称关系可规范排序点对；有向关系保留起点与终点。多个断言可以复用证据，避免重复。

### 7.1 知识点 ID 不保证跨重建稳定

现有 ID 来自结构节点编号和分段，见 [core/kp_build.py](D:/study_agent/core/kp_build.py:3317)。重新总结后，同一个字符串可能代表不同内容，不同字符串也可能指相近内容。

- 技术键使用学科内部身份、doc_id、kp_id 和内容版本哈希；对规范化名称、正文、要点、页码、来源及原文哈希计算，排除时间戳等运行元数据。
- 内容改变时旧关系标过期并暂不展示，生成新的候选。
- 用户反馈迁移必须检查来源、语义、页面和唯一性；拆分、合并和不确定情况须人工选择。原笔记和复习记录不自动改写。
- 学科隔离不只依赖显示名；冻结学科 DB 和输出路径。跨学科未来需明确启用，并处理不同库中 doc_id 相同。
- 重入库可更换 chunk ID；通过内容哈希、页码、摘录重新验证，不能只靠旧 ID 猜测。

### 7.2 发布一致性与断点续跑

后台生成新的 build_id，基于固定学科和数据版本的只读快照计算，在旁路库暂存。提交前重新比较课件和原文版本；一致才单事务切换为 current，不一致则标记过期并重新排队。读者只看到完整旧版本或完整新版本。

相同学科和输入版本采用 single-flight，落盘 checkpoint；失败后只续跑未完成对象。取消仅阻止尚未发出的调用，不假设超时请求一定没有在服务端执行。保留历史与用户反馈，避免重新入库导致错误迁移。

### 8.1 避免拖慢入库和知识点总结

总结成功后只投递“本课件变了”的低优先级增量任务，不在主任务内同步做全库两两比较。本地向量/规则批量与 CPU 使用受限；事实抽取和模型核验放独立队列。

现有 [model_slot](D:/study_agent/core/kp_build.py:2631) 是共享信号量，不能仅凭它声称实现优先级。需要真正的可观测优先队列或额度分配，避免后台工作抢占主要管线；同时防止嵌套取槽死锁。

发布前测试功能关闭、启用但后台空闲、启用且后台运行三组的主任务耗时。索引未生成时显示状态和明确的生成入口，不在“查看”时偷偷触发付费请求。

## 九、成本与速度估算

309 个可用点若做无向全两两比较为 47,586 对；排除同课件后仍有 41,964 对。不要逐对付费询问模型，应先本地召回、去重和筛选。

309 个 512 维 float32 向量原始数据约 0.60 MiB；一万个约 19.5 MiB，不含索引和元数据。目前优先 SQLite + NumPy，没必要先部署图数据库或向量数据库。规模增长后根据实测再考虑 ANN 索引。

按目前 10 份课件，每份内部最多 6 个点一批，309 点理论上是 56 批。实际取决于可用证据、输入 token、输出长度、拆批和失败情况，可能更多；这不是已运行次数或预算承诺。

先抽样 20～30 个点，设调用次数及总 token 硬上限，记录输入、缓存输入、输出（含服务商计费的推理 token）、调用数与实际单价。价格和缓存规则以用户实际供应商及当日价格为准，usage 不报告时显示未知，不记为零。小样验证后再决定是否全库构建。

本地耗时依赖模型冷启动、长度、负载和批大小；响应时间目标必须实测，不得用一次探查的时间保证产品性能。

## 十、评测：证明确实优于相似度

### 10.1 标注集

跨不同课件抽 30～50 个起点，覆盖总论/具体药物、机制/应用、中英缩写、图文和来源不足。由熟悉课程的人标注：

- 相关程度：0 不相关、1 弱线索、2 值得推荐。
- 多选教学关系；先修和作用关系单独标方向。
- 两侧来源是否支持解释、条件是否遗漏。
- 需要中间环节的桥梁及无法判断的样本。
- 难负例：同名异义、类似药名、激动/阻断、受体亚型、中枢/外周及同章但无实质联系。

合并各方法候选、去重、打乱盲评，再补人工主动发现的候选。没有任何方法召回的关系仍可能漏标，因此 Recall@K 仅对已知标注集合有效。保留标注者分歧和无法判断，不让同一个模型自生成自评作为最终标准。

按课件/文档分组划分，并保留时间上后加入的课件，避免同一页改写同时用于调参和测试。当前课件数少，应采用多次分组评估，报告样本量与不确定区间。

### 10.2 消融组

A. 现有资料块混合检索再映射到知识点。  
B. 知识点标题＋总结的本地向量相似度。  
C. B＋关键词/别名/RRF＋本地重排。  
D. C＋一跳关系与证据。  
E. D＋双跳桥梁和方向检查。  
F. E＋受控模型解释和关系判断。

使用同一测试集、候选预算与课件配额。D/E/F 若没有稳定收益，保留更简单且可靠的版本。

### 10.3 指标和拟定目标

以下都是发布前建议目标，不是已测结果：

- 已标注集合的 Recall@20 和 NDCG@10；先修和桥梁子集单独计算。
- 前五条“值得看且关系表达正确”的 Precision@5，目标至少 90%；同时报告审核数和置信区间。
- 方向、类型、错误因果、错误概念合并、证据支持和拒答正确性。分开计数“引用存在”和“引用支持结论”。
- 桥梁覆盖率、路径每步可核验率，以及错误图边造成的误导。
- 热缓存本地查询 p95 小于 1.5 秒作为初始目标；冷启动和付费模型分析另计。
- 后台关联任务运行时，主入库＋总结耗时相对关闭功能增加不超过约 10%，需真实测量。
- 调用数、tokens、费用、缓存命中、失败和续跑率。

后续可探索同一用户不同时段的对照，记录一周及一个月后的主动回忆；少量个人记录不能证明严格因果。

## 十二、失败情形

1. 总结超出原文：原文/图片不足时降级，不把摘要当唯一证据。
2. 缩写歧义：按上下文和来源拆分，不能判断时不合并。
3. 先修关系成环：仅对先修子图检测，移入待审核；其他关系无需强制无环。
4. 高频概念导致图枢纽：降权、限制分支并保持来源多样性。
5. 知识点、原文或规则变化：标记旧关系过期，增量重算并保留反馈历史。
6. 超时或 JSON 截断：保留成功部分，不无限重试，结果未知和预算如实展示。
7. 没有相关结果：明确显示无充分依据，不为凑数展示无关内容。
8. 机器识图证据：标记为图像描述并可打开原图。
9. 重排或模型不可用：回落已有图和本地混合检索，显示降级状态。
10. 用户反馈偏差：点击和停留仅作弱信号，不把没点击自动当负例。
